# 앱 전용 WARP 등록과 저장 상태

일반 점검은 기본 연결이며 WARP 등록이 필수가 아니다. 고급 모드에서 앱 전용 WARP를 선택한 점검만 터널을 사용한다. Windows 앱은 사용자가 약관 동의를 표시하고 등록을 실행한 경우에만 앱 전용 usque 장치를 등록한다. 상태 조회, 점검 시작, 앱 재시작은 장치를 등록하지 않는다. 동시에 등록을 실행해도 한 번만 처리하며, 이미 유효한 설정이 있으면 재사용한다.

설정은 앱 데이터 폴더의 `warp/config.json`에 평문 JSON으로 저장한다. 폴더는 생성 시점부터 현재 Windows 사용자와 SYSTEM만 접근하도록 제한한다. 생성된 파일도 상속을 해제하고 같은 접근 권한을 검증한다. 디스크 암호화나 동일 사용자로 실행되는 다른 프로세스로부터의 격리를 제공하는 방식은 아니다. 공식 WARP 클라이언트의 설정이나 키는 읽지 않는다.

`ready`는 저장된 설정과 번들 usque 4.2.1 실행 파일 검증이 통과했다는 뜻이다. 실제 터널 연결 성공을 뜻하지 않는다. 앱 전용 WARP를 선택한 공개 사이트 점검만 별도의 준비와 연결 검증을 통과해야 진행한다. 기본 연결은 WARP 설정·실행 파일을 조회하지 않는다. 수동 평가용으로 허용된 정확한 비공개 원점과 저장된 Case 열기는 미등록 상태에서도 사용할 수 있다.

등록 시작 전에 `warp/registration-attempt` 기록을 남긴다. 장치 생성 뒤 설정 저장이 실패했거나 완료 여부가 불확실하면 자동 재등록하지 않는다. `registration-failed` 상태에서 앱을 다시 시작하거나 등록을 반복해도 새 장치를 만들지 않는다. 이 경우 담당자가 기존 장치와 설정 저장 상태를 확인해야 하며, 실패 기록을 임의로 삭제해서 재시도하지 않는다.

실패 사유는 제한된 코드만 전달한다. `config-permission`은 저장 권한 검증 실패, `config-invalid`는 설정 형식 문제, `binary-missing`은 번들 누락, `binary-integrity`는 실행 파일 검증 실패를 뜻한다. `preparation-failed`와 `tunnel-exited`는 점검 연결 준비 또는 연결 유지 실패다. 등록 자식 프로세스의 원문 출력과 설정 내용은 진단·IPC에 담지 않는다.

점검 도중 연결이 실패하면 이미 확인한 공식 결과를 보존하고 Case 상태를 `failed`로 저장한다. Case 설정의 `transportFailure.scope`는 `incomplete`이며, 점검하지 못한 대상을 정상 또는 탐지 0건으로 확정하지 않는다. 선택한 연결은 `settings.connection`, 관측한 연결은 제한된 `transport` 메타데이터에 저장하고 공식 JSON 형식은 바꾸지 않는다. 과거 Case에 없는 연결 정보를 추정해서 채우지 않는다.
