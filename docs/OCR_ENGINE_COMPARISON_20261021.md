# 다른 OCR 비교와 응시료·삼성 축소본 오탐 보정

2026-10-21, `dev/bootstrap` / HEAD `56fd3563e031ef1850e88b4fdac0c39ead08eea5`의
미커밋 변경이다. 응시료 할인 광고와 삼성 휴대전화 축소본의 잘못된 판정 경로를
수정했다. 다른 OCR3종도 비교했지만 남은 우주선/WINNER/MACHUJA3누락을 신뢰할
수 있게 해결하지 못했다. 새 인식기 도입이나 세 누락 해결을 주장하지 않는다.
Windows 검증은 사용자 요청대로 계속 보류한다.

## 두 오탐의 원인과 수정

응시료 광고의 Tesseract 원문은 `연속 만점자의 최신 실전 전략`, `응시료 1만원 할인`
등을 담지만 `토익`을 잃었다. 평균 confidence0.76이 기존0.70 fallback 기준보다 높아
Korean PP-OCR를 건너뛴다. 고정 v2 helper margin은+.007608이다. 기존 PP-OCR로
원본550×400을 읽으면 `토익 연속 만점자의 최신 실전 전략`, `기간 한정|토익 응시료
1만원 할인 + 시크릿 자료집 제공`을 복구한다. confidence0.907, margin-.042180이다.

`packages/detection/src/scan.ts`에서 직접 규칙 양성은 그대로 보존하고, 의미 비교만으로
양성이 된 Tesseract PNG를 기존 PP 기본 인식기로 검증한다. `neural-review`는 같은
killable child/모델/자원 제한을 재사용한다. 실제 PP 원문과 그 원문의 의미·공공안내
판정으로 선택 결과를 교체하며, 이전 원문은 `ocrAlternatives`에 남는다. 인식 실패,
비정보성 문구, 의미 검증의 모델 오류·예산 부족은 기존 양성을 보존한다. 검토 중
발견한 후속 의미 검증 실패 시 양성 소실 경로도 수정하고 회귀검사로 확인했다.

삼성206×62 축소본은 기본 PP가 `Golary 12s Series`(confidence.771142,
margin-.005696)를 읽고 4x가 `alary126 5e`(.630509,+.003649)를 읽는다.
더 짧고 신뢰도도 낮은 동일 인식기의 문구를 단순히 OR 결합해 오탐했다. 같은 PP의
대안이 **confidence와 Unicode 문자 수 모두 감소**하면 의미 비교만으로 승격하지
않도록 고쳤다. 직접 규칙을 만족하는 실제 광고 문구는 여전히 채택한다. 서로 다른
인식기 confidence를 직접 비교하지 않는다. 두 신호 중 하나만 감소한 실제 양성도
유지한다. 낮은 confidence 자체가 오인식을 증명한다고 주장하지 않는다.

모델·19비교문장·임계값0·공공안내 제외·공식 JSON·GIF 선택·수집/시간 상한은
그대로다. 교육 키워드 예외나 삼성 허용목록, 수동 문자 교정은 추가하지 않았다.
선택된 OCR과 helper 점수는 항상 같은 원문이며 실제 미선택 원문도 보존한다.
PNG 검증만 구현했으므로 JPEG/WebP 같은 경로의 일반화를 주장하지 않는다.

## 다른 인식기의 실제 비교와 기각

`artifacts/ocr-engine-comparison-20261021/alternative-ocr/`에 pinned 모델·가중치
해시·환경·검출 영역·모든 원문·스크립트를 남겼다. 알려진3누락·응시료·삼성5개는
개발 자료이며 새 독립 광고 검증으로 세지 않는다. 원본 픽셀, 자동 검출 영역만 사용했고
광고주 사전·수작업 크롭 선택·정답 전사·문자 교정·정답 프롬프트를 넣지 않았다.

- EasyOCR1.7.2 Korean G2(VGG/BiLSTM/CTC)와 G1(ResNet/BiLSTM/CTC), CRAFT 기본/4x:
  남은3개의 핵심 카테고리/제안 문구를 충분히 복구하지 못했다. G1은 응시료 광고의
  토익 문맥을 읽지만 이미 설치된 PP도 읽으므로 추가 모델을 넣을 근거가 아니다.
  삼성은 검출 영역0개다. 빈 결과를 정상 광고 분류 성공으로 세지 않았다.
- `team-lucid/trocr-small-korean`, revision`33e0a37bee9b4715f974804a95e7e53323fbe4b7`:
  DeiT/TrOCR transformer로 구조가 다르다. FP32 CPU2threads,384×384 bicubic,
  greedy/beam1/최대64tokens/no-cache로 검증했다. PP/CRAFT 자동 영역의 모든 줄을
  검출 방식별로 분리해 읽고 합성했다. 서로 다른 영역 방식의 문구를 한 원문으로
  이어붙이지 않았다. 일부 실제 `첫충전40%`, `신규첫중30%신규미션`을 읽지만 후자를
  `충`으로 바꾸지 않았다. WINNER는 여전히 로고·숫자·작은 문구가 깨진다.
- 고정 v2 비교에서 PP 기본 자동 영역의 TrOCR 결과는 세 누락 모두 점수상 양성이지만
  실제 카테고리를 복구하지 않은 무의미한 문자도 섞인다. 같은 경로의 기존 정상
  PNG10개(그중 삼성/LG축소6개)에서는 KB5·삼성폰·LG제휴 **3오탐**이 생겼다.
  점수만 오른3/3을 탐지 개선으로 채택하지 않았다. 합성 정상 로고도 별도 오탐했다.
- 흰색·회색 전체 이미지를 무조건 생성 인식하면 긴 허구 문구를 출력했다. 실제
  detector→TrOCR 경로에서는 흰색/회색/잡음3개에 영역0개여서 호출하지 않았다.
  이 합성 제어를 실제 정상 광고 분모나 현장 오탐률에 넣지 않는다.
- PP-OCRv6 medium의 공식 inference vocabulary도 검사했으나 Hangul syllable이0개라
  한국어 교체 후보에서 제외했다. 가중치는 내려받지 않았다.

모델 구조·전처리는 [EasyOCR 공식 소스](https://github.com/JaidedAI/EasyOCR/tree/v1.7.2),
[TrOCR 모델 작성자 카드](https://huggingface.co/team-lucid/trocr-small-korean),
[PP-OCRv6 공식 저장소](https://huggingface.co/PaddlePaddle/PP-OCRv6_medium_rec_onnx)와
pinned metadata를 확인했다.

EasyOCR/TrOCR는 제품 의존성이나 Python 런타임으로 넣지 않았다. ONNX export도
품질 gate 실패로 진행하지 않았다. 프로브의 단발성 시간은 엔진 진단용이며 최종
canonical 전후 처리 시간과 직접 비교하지 않는다. 원본 환경/모델은 작업 소유 tmpfs에
있고 제품은 그 위치에 의존하지 않는다. 모델 metadata/원문/환경 manifest는 저장했다.
