# 검토 화면 변경과 웹 검증

2026-10-10 관측. UI 변경은 웹 빌드와 실제 React 화면 조작으로 검증한다.
설치는 패키지·업그레이드·데이터 보존 경계에 한정한다.

점검 설정은 주소·유효 범위·시작 동작을 한 카드에 모았다. 상세 설정을 닫아도
현재 모드·페이지·시간 제한을 읽을 수 있다. 저장된 케이스와 일괄 점검 진입을
구분했다. 데스크톱 결과는 왼쪽 요약·저장, 오른쪽 검색·검토 목록으로 배치했다.
원문 근거 화면은 상단에 고정된 목록 복귀·검토 버튼을 제공한다. 좁은 화면에서
항목명과 값을 세로로 배치하여 원문이 전체 너비를 사용한다.

결과가 처음 준비되면 제목으로 초점을 이동하고 후속 범위 조회에서는 초점을
빼앗지 않는다. 검토 목록으로 이동하는 링크와 기존 근거 버튼으로의 초점 복귀를
유지한다. 일괄 검토는 묶음의 범위 상세 안에서 시작하며 확인 절차를 유지한다.
브라우저 미리보기는 영구 저장을 지원하지 않는다는 사실을 표시하며 지원하지
않는 Case IPC를 호출해 저장 실패처럼 표시하지 않는다. 실제 데스크톱 저장 오류는
계속 표시한다. 공식 JSON·원문·탐지 정책은 이번 UI 변경으로 바꾸지 않는다.

## OBSERVED

- 타입 검사, 변경 파일 lint, 웹 테스트 107개/18파일 통과.
- `npm run build -w apps/web` 성공. 기존 큰 export/target-import chunk 경고는 남는다.
- `node benchmarks/ui-v21-workspace-smoke.mjs`: 실제 빌드된 UI와 Tauri adapter에서
  617건·19묶음 fixture를 조회했다. 파일 기반 시험 IPC를 사용했으며 native 실행이 아니다.
- 1366×768, 본문 17px: 이전 `50941bd` 웹 산출물에서 첫 세 행의 마지막 하단은
  830.25px, 변경 후 748.25px. 같은 fixture·viewport·시험 Case 응답을 사용했다.
- 320px: 가로 넘침 없음. 근거 원문 너비 300px, 복귀 버튼 y=24–72px.
  200% CSS 확대에서도 가로 넘침 없음. 실제 OS 배율/브라우저 확대의 대체 인증은 아니다.
- 검색·기법·검토 필터, 20/50건 페이지 전환, 묶음 범위 확인, 검토 메모,
  키보드 진입·복귀, 결과 제목 초점과 목록 이동을 실행했다.
- 공식 JSON 직렬화 바이트 동일. 실제 XLSX 생성에서 공식 617건·메모 유지,
  수식 셀 없음. native 저장 창은 이 웹 검증에서 시험 응답으로 대체했다.
- 실제 BrowserHost 미리보기에서 영구 저장 실패 알림 없음, 예시·휘발성 메모 안내 표시.
  두 모드 모두 외부 요청·pageerror 0건.

CI `37965596260`의 Linux 검사에서는 별도 취소 fixture가 20초 test timeout에 걸렸다
(490 pass, 1 fail, 1 skip). 같은 fixture의 단독 실행은 288ms에 통과했다. 실패 원인이
운영 코드라고 확립하지 않았다. 시험 자체의 20초 제한이 스캔의 20초 예산과 같아
시작·정리까지 구분하지 못하므로 harness를 40초로 분리하고, 실제 `/slow` 요청에서
취소를 관측한 뒤 결과 확정이 5초 안에 끝나는지를 별도로 검사한다. 운영 스캔 예산은
바꾸지 않는다. fixture listener를 먼저 닫고 연결을 정리한다. 변경 후 단독 fixture는
266ms에 통과했다. 후속 `b30dc92` CI `37967025068`의 Linux verify도 통과했다.
원래 timeout을 운영 코드 결함으로 확정하거나 성공 기록으로 바꾸지 않는다.

추가 683×384 CSS viewport 검증에서는 결과 제목이 한 글자씩 세로로 밀리는 회귀를
발견했다. 가로 넘침 여부만으로 읽기 가능성을 판단할 수 없었다. 결과 header를
줄바꿈 가능한 flex 배치로 수정했고, 같은 조건에서 제목은 159×48px로 읽을 수 있게
표시됐다. 이 너비의 제목 폭·높이와 가로 넘침을 실제 화면 회귀에 추가했다.
수정 후 617건 workflow, 1366/320px, CSS zoom, BrowserHost 검증을 다시 통과했다.

실행 결과와 전후 화면은 인계 증거의 `ui-adoption/{before,after}/`에 있다.
전후 화면은 baseline source를 저장소에 덮어쓰지 않고, 기존 509 웹 산출물과
새 웹 산출물을 각각 실행해 얻었다. 재실행은 root에서 다음 순서다.

```sh
npm ci
npm run build
V21_EVIDENCE_DIR=/tmp/krds-ui-evidence node benchmarks/ui-v21-workspace-smoke.mjs
```

## NOT_RUN

이 UI 변경이 포함된 설치본의 native 사용자 과업과 실제 사용자·보조기기 수용은
아직 실행하지 않았다. 이전 509 설치본의 native 검증과 새 웹 검증을 구분한다.
외부 두 사이트의 일괄 점검은 사용자가 승인한 정확한 주소가 없어 실행하지 않았다.
