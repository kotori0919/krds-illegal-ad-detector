## 1. 배경과 목적

지방자치단체·공공기관 웹사이트의 게시글, 댓글, 첨부 이미지, 삽입 프레임에는 도박·
불법 대출·현금화 광고가 들어온다. 이 광고들은 글자색을 배경과 같게 하거나, 투명도를
0으로 두거나, 화면 밖으로 밀거나, 자모를 분해하거나, 키릴·전각 문자로 모양을 흉내
내는 방식으로 육안 점검과 단순 문자열 검색을 동시에 피한다. 기존 점검은 "보이는
화면"만 보므로 숨은 요소에 대해 "확인했다"도 "없다"도 말할 수 없다
(`docs/PLANNING_DOC.md` §1).

목표는 탐지율 숫자가 아니라 **비전문 담당자가 한 번의 점검으로 무엇이 어디에 어떻게
숨어 있었고, 어디까지 확인했고, 무엇을 확인하지 못했는지 설명할 수 있는 산출물**이다.
구체적으로 (1) 주소 하나로 하위 페이지·게시글·댓글·프레임을 수집하고 네 기법을
판별하며, (2) 원문·페이지 주소·선택자·실제 화면 근거를 남기고, (3) 확인하지 못한
페이지를 성공 결과와 분리해 표시하며, (4) 공식 JSON과 엑셀 보고서로 남기고, (5) 이를
Windows 11·무GPU·외부 AI 미접속 환경에서 수행한다 (`PLANNING_DOC.md` §2).

평가 전제는 Windows 11, 4~6코어, 8GB 메모리, GPU 없음, 30분 제한이고 기본 점검
예산은 1500초다 (`PLANNING_DOC.md` §2). 내부 정지 1650초, 공식 상한 1800초, 수용
목표 1200초이며 목표 환경의 기본 동시성은 2다 (`PLANNING_DOC.md` §8.3).

## 2. 대상과 입력

- **입력**: 공공 웹사이트 주소 1개(간단 모드), 또는 CSV·XLSX·JSONL·XML 대상
  목록(고급 모드 일괄). 간단 모드 기본 범위는 최대 200페이지·하위 4단계·최대 25분이다
  (`PLANNING_DOC.md` §6, `docs/USER_MANUAL.md` §간단 모드).
- **수집 범위**: 동일 사이트 BFS, URL 정규화로 중복 제거, 쿼리 **값**은 보존한다.
  메인 프레임 리다이렉트가 진입 호스트를 벗어나면 `external-redirect` 실패로 기록하고,
  외부 iframe은 관측하되 재귀 수집하지 않는다 (`PLANNING_DOC.md` §5.1).
- **상한**: 텍스트 노드 10,000, 소유자 1,000, 전체 원문 1,048,576 코드 유닛,
  소유자당 32,768, 스타일 하위 요소 32개, 프레임 깊이 기본 4, 페이지당 자식 프레임
  15개 (`PLANNING_DOC.md` §3.5).
- **이미지**: 문서당 최대 32후보, 페이지당 인코딩 1,000,000바이트, 개별 원본·변환
  이미지 250,000바이트, 서로 다른 OCR 입력 40개, 보관 자산 40개·2,000,000바이트
  (`PLANNING_DOC.md` §3.4). 이미지 수집은 최대 8페이지다
  (`docs/USER_MANUAL.md` §검증 범위).
- **GIF**: 최대 120프레임을 3초 안에서 살피고 최대 4프레임을 남긴다. APNG·
  애니메이션 WebP·동영상은 대상이 아니다 (`PLANNING_DOC.md` §3.5).

## 3. 네 가지 공식 기법

공식 결과(`result.json`)는 아래 네 기법만 담는다. 그 밖의 단서는 `result_extra.json`의
`ETC`로 분리한다 (`README.md` §Scoring, `docs/PLANNING_DOC.md` §3.2).

| 기법 | 판별 내용 | 위치 결정 |
| --- | --- | --- |
| `HOMOGLYPH` | 전각 문자, ASCII 대소문자 폴딩, UTS #39 15.1.0 기준 키릴·라틴 유사자, 매칭어 내부 구두점, 완전한 라틴 `casino` 리트 표기 | 원문 UTF-16 오프셋 역추적 |
| `JAMO` | 유니코드 한글 조합식으로 자모 복원(`ㄷㅐㅊㅜㄹ` → `대출`), 호환 자모 종성 포함 | 동일 |
| `TRANSPARENT` | 문자·배경 대비, alpha, 조상 clipping으로 실제로 보이지 않는 텍스트 | 결정적 선택자 |
| `OFFSCREEN` | 화면 밖 배치·overflow 은닉 등 기하 근거 | 결정적 선택자 |

원문은 덮어쓰지 않는다. `evidence_text`는 정규화 이전 원문을 보존하고 복원·OCR·모델
유래 표현은 별도 필드에 둔다 (`PLANNING_DOC.md` §3.3). 위치는 선택자 생성기가 만들고
실제 문서에서 유일성과 왕복을 검증하며, iframe 내부는 `>>>`로 직렬화한다. 유일성
검증에 실패하면 저장이 차단된다 (같은 절).

## 4. 2축 판정

공식 판정은 두 축이 모두 성립할 때만 만들어진다
(`docs/DETECTION.md`, `PLANNING_DOC.md` §3.2).

```text
기법 근거(TechniqueEvidence) + 광고 근거(IllegalAdEvidence)
  → 후보 근거(CandidateEvidence) → 결정 근거(DecisionEvidence) → 공식 탐지
```

- **A축(은폐)**: `HOMOGLYPH`/`JAMO`/`TRANSPARENT`/`OFFSCREEN`.
- **B축(광고 의미)**: `text-policy-2`. 강한 광고·불법 범주어, 일반어에 붙은 구체적
  제안 의도, 또는 의심스러운 광고 목적지 중 하나가 성립해야 한다. `보장`·`당일`·
  `고액`·`보너스`·`쿠폰`·`무료체험`만으로는 광고로 보지 않는다
  (`PLANNING_DOC.md` §3.2).

이 구조의 핵심은 **은폐 자체를 위반으로 보지 않는다**는 점이다. 접힌 내비게이션,
스크린리더용 텍스트, 애니메이션의 `opacity:0`은 정상 구현이므로 "숨겨져 있으면 탐지"
규칙을 쓰지 않는다. 신고·예방·교육·통계·접근성 안내 문맥은 불법 행위를 언급해도
광고로 판정하지 않는다. 결정 모델은 보조하며 단독 탐지기가 되지 않고, 결정 근거에는
적용 규칙·점수·임계값·통과 여부가 함께 남는다 (같은 절).

**확장 탐지**(`result_extra.json`)는 공식 건수에 더하지 않는다. 종류는
`IMAGE_ONLY_ILLEGAL_AD`, `REUSED_AD_CREATIVE`, `AD_INFRASTRUCTURE_CORRELATION`,
`ZERO_WIDTH_OBFUSCATION` 네 가지다 (`PLANNING_DOC.md` §11).

## 5. 화면 흐름

화면 단계는 **점검 설정 → 사이트 점검 → 결과 검토** 세 개이고, 근거 확인·내보내기·
범위 확인은 결과 단계 안의 동작이다 (`PLANNING_DOC.md` §6, `docs/UX_FLOW.md`). 첫
실행에서 간단(기본) 또는 고급 모드를 고르며, 선택은 기기 환경설정에 저장되고 상단
메뉴에서 바꿀 수 있다. 두 모드는 같은 탐지 엔진·케이스 저장소·검토 writer를 공유하고,
같은 조건에서 모드가 탐지 결과를 바꾸지 않는다 (`docs/ADR/0016-...md`).

**간단 모드** — 주소 입력과 범위 확인 → 점검 시작 → 경과·확인 페이지·탐지·실패 수
확인 → 의심 항목 목록에서 검색·검토 상태 필터 → 항목별 원문·촬영 근거·이유 확인 →
판단·메모 입력 후 "검토 완료·다음" → 엑셀 보고서 저장. 간단 모드에는 빠른 점검·깊이
입력·OCR 설정·그래프·일괄 가져오기 버튼을 두지 않는다 (`PLANNING_DOC.md` §6).

**고급 모드** — 한 사이트 또는 여러 사이트, 상세 설정(자동 200페이지·4단계·25분 /
빠른 50페이지·2단계·10분 / 직접 60~1500초), 대상 목록 사전 검증 후 사이트별 순차 실행.
일괄 작업 묶음(그룹)은 `<cases>/groups/<uuid>.json`에 저장되어 재시작 후 복원되고,
저장된 판단으로 통합 XLSX를 다시 만든다(`bdcc0e8`; 최종 설치본에서 공개 두 대상 저장·실제 재시작·통합 XLSX 셀 동일을 관측했으며, 판단·메모 포함 두 대상 수용은 별도 미실행이다).
결과 화면은 `탐지 항목 | 점검 범위 | 인프라 분석` 세 영역이고, 인프라 분석은 저장된
케이스 하나의 근거만 읽으며 새 외부 접속을 하지 않는다 (`PLANNING_DOC.md` §7).

두 모드 모두 **탐지 0건은 "확인 범위와 함께 관측 0건"** 으로 표현하고 안전을 보증하지
않는다. 접근 실패·시간 초과는 [점검 범위]에 이유와 함께 남고 보고서에도 범위 제한이
기록된다 (`PLANNING_DOC.md` §6, §7).

## 6. 증거·검토·내보내기

- **공식 원본 불변**: 공식 JSON은 선택적 근거·OCR·그래프보다 먼저 확정되고, 이후
  단계가 실패해도 이미 확정된 결과를 무효화하지 않는다 (`PLANNING_DOC.md` §4).
  파일은 `result.json` / `result_extra.json` / `review.json`으로 분리한다
  (`docs/DATA_HANDLING_KO.md`).
- **저장 전 검증**: JSON 파싱, UTF-8 BOM 없음, 필수 `meta`·판정 필드, ID 유일성,
  기법 값 4종, `url+location+technique` 중복, URL 형식, 선택자 유일성·왕복 중
  하나라도 실패하면 저장이 차단된다 (`PLANNING_DOC.md` §5.3).
- **화면 근거**: 탐지 요소의 실제 JPEG 크롭을 세션 범위 자산으로 보관하고 호스트를
  통해서만 읽는다. 페이지가 임의 파일 경로를 지정할 수 없다 (`PLANNING_DOC.md` §5.2).
- **검토 기록**: 읽음 상태, 담당자 판단(판단 전·위반 의심·정상으로 판단·추가 근거
  필요), 메모를 자동 저장한다. 저장 실패 시 편집을 유지하고 재시도하며, 원본 탐지
  수와 `is_violation`은 바뀌지 않는다 (`PLANNING_DOC.md` §5.3).
- **엑셀 보고서**: 점검 요약, 반복 항목, 탐지 상세, 페이지·점검 범위, 추가 분석,
  검토 기록 시트로 구성되고 여러 대상이면 대상 요약 시트가 추가된다. 원문·메모는
  문자열 셀로 기록해 수식·외부 링크로 해석되지 않는다 (`PLANNING_DOC.md` §5.3,
  `docs/USER_MANUAL.md` §결과 파일과 해석).
- **실제 관측**: 617건 결과의 XLSX 618행(머리글 포함)·메모 포함·공식 JSON bytes 동일·
  WARP 호출 0·page error 0 (`docs/ADOPTION_LEDGER.md` §「2026-10-20 일반 연결·화면 모드·단일 사례 인프라 초기 구현」 검증 표). 이 값은
  브라우저/Tauri adapter replay이며 Windows native 실행이 아니다.
- **이전 Windows native 관측(v3)**: 이전 후보 `0361562d…`를 Windows 11에 설치해 loopback fixture 17건
  탐지·확인 15페이지·실패 0·15.4초(v2와 순서·문구까지 동일한 17개 튜플), 판단 `광고 의심`·
  메모 영속, 공식 JSON 4,586 B(BOM 없음, sha256 `afe18685…018e`, 저장 결과와 byte-identical),
  XLSX 16,522 B, 재시작 후 복원을 관측했다 (`artifacts/win-verify-20261023/README.md` v3 절,
  `RECEIPT-v3.json`, `exports-v3/`). 강화된 이미지 광고 규칙은 이 fixture에 배너가 없어
  Windows에서 실행되지 않았고, 그 근거는 Linux 190입력 재측정(60/60·0/74·17/18·0/38)이다.

## 7. 배포 형태

Tauri 2 기반 NSIS 설치 파일 하나로 배포한다. 설치 후 Node, 개발 저장소, 별도
Playwright·OCR 모델 설치가 필요 없다. 앱 식별자는 `kr.go.nia.illegal-ad-detector`이고
케이스는 `%APPDATA%\kr.go.nia.illegal-ad-detector\cases\<케이스 번호>\`에 저장된다
(`PLANNING_DOC.md` §8.1, `docs/OPERATIONS_GUIDE_KO.md`).

- **공식 판정은 오프라인**: 네 기법 판정은 로컬 DOM·CSS·기하·유니코드 분석이며 모델이
  없어도 동작한다. OCR·임베딩은 선택적 근거 단계이고 모델은 빌드 시 SHA-256·크기로
  검증해 패키지에 포함하며 점검 중 내려받지 않는다 (`PLANNING_DOC.md` §8.2).
- **무GPU**: 모든 추론은 CPU다. 비전 인코더 `min(6, availableParallelism())`,
  문자 인코더 2스레드, 신경망 OCR 1스레드 (`PLANNING_DOC.md` §8.2).
- **모델 자산**: 문자 FP32 + 이미지 8비트, 6개 파일 `1,312,154,937`바이트
  (`PLANNING_DOC.md` §8.2, `docs/BUILD_MANUAL.md` §첫 빌드의 네트워크 요구).
- **설치 크기**: 현재 후보 설치 파일 `746,947,332` B(712.34 MiB).
  `onnxruntime-node`의 타 플랫폼 바이너리를 staging에서 제외하고 모델을 포함한 크기다.
  파일 식별과 검증은 `EVIDENCE_INDEX.md` §1, 빌드 원장은
  `ADOPTION_LEDGER.md`의 재개 이후 절을 따른다.
- **제약**: WebView2가 없으면 설치 관리자가 bootstrapper를 내려받으므로 네트워크가
  필요하고, 이 방식의 오프라인 설치는 검증하지 않았다. 현재 설치 파일은 코드 서명이
  없다 (`PLANNING_DOC.md` §8.1).

패키지된 워커로 측정된 Windows 기록이 있다(2026-10-07 통합 후보,
Windows 11 VM 4 논리 CPU·8GiB·무GPU, 200페이지 시나리오, 단일 실행): 워커 1→4에서
347.131 / 174.271 / 112.477 / 87.849초, 피크 메모리 425.4 / 433.1 / 537.5 / 781.9 MiB
(`docs/PLANNING_DOC.md` §8.3, `docs/PERF.md`). 이는 설치된 UI가 아니라 패키지된 워커
측정이며 통계적 속도 향상 주장이 아니다.

## 8. 기대 효과

정량 효과를 주장할 근거는 아직 없다 (`PLANNING_DOC.md` §9). 현재 근거로 말할 수 있는
범위는 다음과 같다.

- **점검의 반복 가능성**: 같은 기준·같은 조건에서 같은 결과를 내어 담당자 교체나 시점
  차이에 따른 판단 편차를 줄인다.
- **근거 기반 시정 요청**: 원문·페이지 주소·선택자·화면 캡처·판단 근거가 한 건에
  묶여 남아 "무엇을 고쳐야 하는지"를 기술 용어 없이 전달할 수 있다.
- **미확인 범위의 명시**: "점검했으나 0건"과 "점검하지 못함"을 구분해 행정적 책임
  소재를 명확히 한다.
- **외주 점검 보완**: 상시 도구로 1차 스크리닝, 애매한 건만 사람이 검토. 다만 이 운영
  방식의 비용 절감 효과는 측정하지 않았다.

## 9. 독창성

1. **은폐와 광고를 분리한 2축 판정** — 은폐만으로도, 광고 문구만으로도 판정하지 않아
   정상 웹 구현과 인용 사례를 오탐으로 만들지 않는다 (`PLANNING_DOC.md` §10).
2. **위치의 재현성** — 선택자 유일성·왕복 검증과 iframe `>>>` 직렬화로 나중에 같은
   요소를 다시 가리킬 수 있음을 확인한 뒤에만 저장한다.
3. **비용 사다리와 게이트** — 32후보 수집 → Tesseract → 저신뢰 PNG만 PP-OCRv5 →
   규칙 미해결분만 문자 임베딩 → 극단 저해상도만 이미지 임베딩. 공식 판정은 첫 두
   축에서 이미 끝나 있다.
4. **공식 출력과 확장 지능의 분리** — `result.json` / `result_extra.json` /
   `review.json`을 나눠 어떤 확장도 공식 건수를 부풀리지 않는다.
5. **전문가/비전문가 화면 분리** — 같은 엔진 위에 간단·고급 모드를 두고 모드 선택이
   탐지 결과나 네트워크 조건을 바꾸지 않게 했다 (`docs/ADR/0016-...md`).
6. **오프라인 공식 경로** — 모델을 쓰되 모델 없이도 공식 판정이 성립하고, 모델은
   빌드에 고정되어 점검 중 외부 통신을 만들지 않는다.

## 10. 한계

해결됐다고 주장하지 않는 항목이다. 상세와 완화 방향은
[`LIMITATIONS_AND_RISKS.md`](LIMITATIONS_AND_RISKS.md)에 있다.

- **실사이트 이미지 광고 재현율**: 2026-10-14 블랙툰 점검의 공식 탐지 1건은 보이는
  배너가 아니라 `display:none` 조상 아래 숨은 문구였다. 이후 수집 상한 확대 후
  실사이트 재현율은 측정하지 않았다 (`PLANNING_DOC.md` §12).
- **Windows 수용의 범위**: 최종8628ba4a 설치본에서 NIA5페이지·실패0,
  공개 두 대상 저장·실제 재시작 복원2/2, 동일한 통합 XLSX7시트와 실제 Excel 열람을 확인했다.
  소유 단일 양성의 판단·메모·검토 완료 복원과 JSON bytes 불변도 확인했다.
  원래 재현된3개 결함은 최종 설치본에서 검증했지만 전체 E2E·기관 수용으로 표시하지 않는다
  (`VERIFICATION_SUMMARY.md` §3·4).
- **D08 남은 범위**: 공개 NIA·정부24 탐지는0건이며 정부24는 외부 이동으로 blocked다.
  판단·메모 포함 공개 두 대상 통합 수용과 기기 간 그룹 이식은 NOT_RUN이다.
  소유 단일 양성 증거를 두 대상 수용으로 합치지 않는다.
- **이미지 광고·MSVC**: 강화된 이미지 광고의 Windows 실사이트 재현율과 최신 MSVC 제품
  경로는 미실행이다. Linux190입력 역사 측정은 현재 후보의 Windows 재현율이 아니다.
- **사람·보조기기 수용 미실행**: 실제 사용성 평가와 AT 판독은 하지 않았다.
- **서명·배포 채널 미정**: 서명 없는 내부 평가 후보이며 코드 서명·배포 채널이 정해지지
  않았다.
- **성능 근거의 범위**: Windows 수치는 2026-10-07 통합 후보 워커 기준이며 최신 이미지
  분석 경로(문자·이미지 임베딩)를 포함하지 않는다 (`PLANNING_DOC.md` §12).
