# Installation layout

The current NSIS candidate and its installed acceptance evidence are recorded
in [RELEASE_CANDIDATE.md](RELEASE_CANDIDATE.md). Older manually assembled
portable trees are historical component evidence.

## Installed resources

```text
install-dir/
  krds-detector.exe                       # frontend and Tauri configuration embedded
  libunwind.dll                          # GNU LLVM target only
  WebView2Loader.dll                      # GNU LLVM target only; not the WebView2 runtime
  uninstall.exe                          # generated by NSIS
  binaries/
    llvm-LICENSE
    scanner-worker-x86_64-pc-windows-gnu.mjs
    ocr-worker.mjs
    node.exe                             # pinned Node v22.19.0
    node-LICENSE
    ocr-data/
      kor.traineddata.gz
      eng.traineddata.gz
    node_modules/
      playwright-core/
      tesseract.js/
      tesseract.js-core/                  # JS and WASM variants
      ...                                # locked Tesseract runtime dependencies
    ms-playwright/
      chromium_headless_shell-1243/
      ffmpeg-1011/
```

The manifest inventories all 679 packaged files with size and SHA-256.
NSIS-generated uninstall metadata is separate from that payload inventory.
Node resolves external modules through `node_modules/`; a bare
`playwright-core/` sibling does not resolve. The installed scanner uses the
shipped Node, browser and OCR resources without a checkout, a development PATH,
or a populated per-user Playwright cache. The acceptance installation received
no manually copied repair files.

## Resource resolution

The host first resolves the scanner under Tauri's
`$RESOURCE/binaries/scanner-worker-x86_64-pc-windows-gnu.mjs`; existing
exe-adjacent portable resolution remains in the accepted implementation.
Worker-adjacent `node.exe` precedes exe-adjacent Node and PATH lookup. Invocation
is `node <sidecar> <args>`, without a caller-provided shell command.
The browser uses an explicit `PLAYWRIGHT_BROWSERS_PATH` when present, then
worker-adjacent and exe-adjacent resources before the default user cache.
The acceptance environment cleared that override and `NODE_PATH`.

## Provisioning and installation

Tauri's `beforeBuildCommand` builds the frontend, scanner and OCR worker,
stages Korean/English language data, and runs `prepare:windows-runtime`.
That script verifies the pinned Node download, copies locked runtime modules,
and stages Playwright's Windows headless shell and FFmpeg. GNU LLVM builds
also stage the matching loader DLLs and license as described in
[BUILD_MANUAL.md](BUILD_MANUAL.md).

The NSIS configuration installs for the current user. WebView2 provisioning
uses `downloadBootstrapper`; if the runtime is absent, installation needs
network access. Bundled CPU OCR and language data do not establish offline
installer acceptance. The current VM already had WebView2 installed.

Operator exports are saved to a location selected through native Save As.
The observed uninstall retained the export outside the installation directory.
Unicode account paths, absent-WebView2 provisioning and a completely offline
installation were not exercised by this candidate's three release gates.
