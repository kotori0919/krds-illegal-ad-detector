# 블랙툰 배너 누락 원인과 EmbeddingGemma 2 비교

이 문서는 2026-10-21 사용자가 요청한 동일 입력의 로컬 비교 기록이다.
모델은 실험 경로에 연결했으며 제품 기본 탐지 경로와 공식 결과는 변경하지 않았다.
이는 아래 최초 실험 시점의 상태다. 같은 날 후속 문자 전용 제품 통합과 새 자료 검증은
[문자 보조 실제 경로 검증](TEXT_EMBEDDING_INTEGRATION_20261021.md)에 별도 기록한다.
Windows 검증은 계속 보류한다. 아래 비교의 단위는 운영자가 살펴볼 탐지 후보이며,
임베딩이 읽지 못한 문자를 복원하거나 공식 은닉 기법을 추가한 결과가 아니다.

## 입력과 비교 방법

- 보관된 블랙툰 화면의 배너 crop8개: 모두206×62. 원본 광고 자원이나 현장 GIF가 아니다.
- 기존 비교 이미지5개: 합성 로고·상업 문구·공공 안내·도서관 안내4개, 기존 illustration1개.
- 실제 정상 광고6개: 삼성·LG 공식 홈페이지에서 연결된 제품·구매 혜택 홍보 이미지.
  원본과 URL/응답/해시를 보관하고, 흰 배경 합성 및 종횡비 유지206×62 축소본으로 비교했다.
- 추가 합성 혼동 사례6개: 할인·게임 첫충전·도박 신고 교육·카지노 예방·스포츠 뉴스·게임 포인트.
  실제 정상 광고6개와 합성 사례는 결과에서 구분한다. 이25개는 선정된 개발 회귀 입력이며
  공개 웹의 일반적인 재현율/오탐률이나 독립 holdout을 대표하지 않는다.

현재 canonical scanner를 같은 입력에 다시 실행했다. 후보25개를 전부 수집하고 OCR을
완료했으며 byte/후보/OCR 제한에 의한 제외0이었다. 기존 결과는 배너1/8, 음성 비교
오탐0/17이다. official/extra/detail 세 계약 검증도 통과했다. 소유 loopback fixture만
Linux Chromium sandbox 예외를 적용했다. 공개 사이트를 격리 없이 실행하지 않았다.

모델 입력에는 실제 픽셀과 실제 OCR만 전달한다. 파일명·정답·광고 도메인·사람이
읽어 적은 문장을 임베딩 입력에 넣지 않는다. 관측된 외부 목적지 유무는 후보의 독립
근거로만 사용한다. 모든 비교 이미지에 동일하게 외부 href와 banner marker를 붙였다.

`google/embeddinggemma-2` revision `914f7f89142e33e77833254d9c9b90c3cef7303b`를
다운로드하고 고정 upstream LFS SHA-256/크기를 대조했다. local files only,
trust_remote_code=false, Hub/Transformers offline으로 추론했다. 이미지/OCR의 원격 AI
전송은 없다. Apache-2.0 모델 카드와 모델/처리기 파일 해시는 증거에 보존한다.

모델·프롬프트·기준·허용 오차는 첫 추론 전에 `protocol.json`으로 고정했다.
도박 광고 설명8개와 정상/공공 안내 설명8개를 각각 임베딩하고, 가장 높은 도박 설명
코사인 점수에서 가장 높은 정상 설명 점수를 뺀다. 주 비교는 이 차이>=0.05이고,
관측된 외부 목적지가 있는 경우를 기존 결과에 더한다. 점수는 확률이 아니다.
차이>=0인 최대 점수 분류는 사전에 정한 진단용 대조이며 자동 채택 기준이 아니다.
이 평가 이미지로 프롬프트·모델·기준을 학습하거나 결과를 본 뒤 조정하지 않았다.

문자만, 이미지만, 이미지+실제 OCR, 흰 이미지+동일 OCR을 분리한다. 마지막 대조는
텍스트를 그대로 두고 픽셀만 바꿔 이미지의 실제 기여를 확인한다. seed17/29/43은
고정된 모델의 반복 추론 번호이며 학습 seed의 불확실성을 의미하지 않는다.
float32, CPU2스레드, batch4, 정규화768차원, 반복 출력 허용 오차1e-5를 사용한다.

## 누락된7개 각각의 원인

| 배너 | 실제 OCR에서 사라진/바뀐 근거 | 판정에 미친 영향 |
| --- | --- | --- |
| 1 크롬하츠 | `페이백10%`→`페이백10x`, `콤프4%`의%와70% 누락 | 첫충·페이백·콤프는 있지만 유효한 백분율을 읽지 못해 거절 |
| 2 금맥 | `환전`→`완전`, 신규70% 등의 일부 문구 손실 | 지원 범주인 환전이 사라지고 콤프만 남음. 다른 복합 입금 조건도 부족 |
| 3 예스 | `첫충`→`첫중`, `페이백`→`매이백`, 콤프 손실 | 서로 독립된 도박 프로모션 단어가 없어 의미 조건 실패 |
| 4 레드벨벳 | `%`→`×/x`, `페이백`→`메이백`, `콤프`→`금프`, 큰 입금 문구 누락 | 백분율·정확한 용어·입금 단서가 함께 손실 |
| 5 마카오 | 첫충·페이백 표제 누락, `입출금`→`입들금` | 콤프와 숫자만으로는 부족. 입출금을 바르게 읽는 것만으로도 현재 정확 일치 입금 조건을 충족하지 못함 |
| 6 뽕벳 | 카지노 범주와 첫충·페이백·고액전용 등 대부분의 핵심 문구/숫자 손실 | 콤프 일부만으로는 범주/제안 조합을 만들 수 없음 |
| 8 호빵맨 | `콤프`→`록프`, `입금`→`입급`, 첫충 누락 | 페이백10%는 읽었지만 두 번째 핵심 용어와 입금 근거가 없어 거절 |

모두 수집/OCR 완료 뒤 의미 조건에서 탈락했다. 이번 고정 입력에서 예산 확대만으로
해결되지 않는 이유다. OCR 평균 confidence 약0.77~0.94가 핵심 글자의 정확성을 보장하지
않았다. 저해상도·장식 글꼴이 원인이라는 해석은 픽셀/오독의 대조에 근거한 추론이다.
원본 고해상도 이미지나 애니메이션을 확보하지 못했으므로 해상도/시간의 원인을 분리한
측정으로 주장하지 않는다. 정적 화면 crop만으로 섬광 때문에 빠졌다고 단정할 수도 없다.

진단용으로 다른 입력을 고정하고 사람이 확인한 OCR 글자 일부만 바꾸면 1번의
`10x`→`10%`, 2번의 `완전`→`환전`, 3번의 세 핵심 용어 복구, 8번의 콤프/입금 복구가
기존 규칙을 통과시켰다. 반면4번의 백분율/페이백/콤프만 복구하거나5번의 입출금만
복구하면 여전히 거절됐다. OCR 오류와 정확한 단서 조합 요구가 겹친 결과다.
이 수동 문장 대조는 원인 확인이며 실제 OCR 개선 수치에 포함하지 않는다.

이전 RapidOCR 및 단순 확대 실험의 원본 crop SHA-256도 대조했다. 같은 입력에서
`10%`→`10x`, `환전`→`완전`, `페이백`→`메이백`, `콤프`→`록프`가 반복됐다.
따라서 Node 경로의 선택 상한이나 판정 규칙만으로 설명되는 실패는 아니다.
이 자료는 이전 실행 기록이며 이번 회차에 두 OCR 구현을 새로 벤치마크한 것으로
주장하지 않는다. 대응 원문은 `prior-ocr-crosscheck.json`에 따로 보관했다.

세 반복의 판정/코사인 값/벡터가 모두 같았다(벡터 최대 차이0, 허용 오차1e-5).
다음 표는 모두 기존 결과를 유지하고 임베딩 후보를 더한 결과다. 분모는 동일한
블랙툰8개와 음성 비교17개다. ‘재현율’은 이 고정 회귀 입력에서의 검토 후보 재현율이다.

주 비교에서 새로 잡은 것은1번 크롬하츠와5번 마카오다. 기존7번 앙벳을 포함해3개다.
흰 이미지 대조에서는5번이 사라져, 같은 OCR에서 픽셀의 추가 기여가1개 확인됐다.
실제 이미지/흰 이미지 벡터의 최대 차이는0.083849로 수치 오차보다 컸다.

차이0의 이미지+OCR 오탐은 합성 `normal-sports-news`다. ‘스포츠 경기 분석 뉴스 /
토토 도박 피해 예방 / 교육자료 무료 배포’를 도박 광고에 더 가깝다고 분류했다.
이미지만 사용하면 삼성/LG 중 LG TV·회원 혜택 실제 광고2개를 비롯해 정상 게임과
예방 안내까지 총7개를 잘못 분류했다. 그림의 유사도를 불법성 판정으로 대체할 수 없다.

### 기존 공공안내 제외 규칙을 결합한 추가 대조

위 오탐을 본 뒤, **기존 canonical `semanticGate`의 `PUBLIC_INFORMATION` 제외
규칙을 유지하는 조합**을 추가로 실행했다. 모델·프롬프트·OCR·점수 기준은 바꾸지
않고 관측된 기존 제외 사유만 재사용했다. 결과는 세 반복에서 동일했다.

| 추가 조합: 차이>=0 + 기존 공공안내 제외 | 배너 후보 | 오탐 |
| --- | --- | --- |
| 문자 임베딩 보조 | 7/8 | 0/17 |
| 이미지 임베딩 보조 | 8/8 | 4/17 |
| 이미지+OCR 보조 | 8/8 | 0/17 |

이미지+OCR의 예방 뉴스 오탐1개가 기존 제외 규칙으로 차단됐다. 이 조합은
`POSTHOC_EXISTING_POLICY_COMPOSITION`이다. **사후 추가한 조합의8/8을 사전 고정
주 비교의3/8이나 독립 검증 성능과 혼동하면 안 된다.** 원래의 오탐 기록도 그대로
보존한다. 이 자료에 맞춰 임계값을 다시 고르거나 사람의 교정 문장을 모델에 넣지 않았다.

## 처리 비용과 적용 판단

AMD Ryzen7 9700X, RAM 약32GiB, Linux, Python3.12.13, torch2.14.1+cpu,
torchvision0.29.1+cpu, Transformers5.20.2, SentenceTransformers6.1.0,
NumPy2.5.4, CPU2스레드/float32, batch4였다. 사용한 텍스트+시각 인코더의 활성
파라미터는438,760,448개다(오디오 제외). 추론에는 이미지와 문자만 사용했다.

|25개 입력의 추가 모델 처리|3회 중앙값|최소~최대|
| --- | --- | --- |
| OCR 문자만 | 1.366초 | 1.352~1.374초 |
| 이미지만 | 146.821초 | 146.255~147.358초 |
| 이미지+OCR | 148.514초 | 148.313~149.200초 |
| 흰 이미지+OCR | 148.815초 | 148.292~149.374초 |

이미지+OCR의 평균 환산은 약5.94초/장이며 개별 p95가 아니다. 별도 baseline의
수집+OCR+판정 전체 실행은11.197초였지만 모델 표는 **추가 추론만**의 시간이다.
이 두 값을 같은 종류의 end-to-end 실행으로 비교하지 않는다. 모델 로드는 이미
내려받은 shm cache에서1.574초, Python 자체 peak RSS는3155.2MiB(약3.08GiB)였다.
전체 앱/프로세스 트리/파일 캐시 합산 메모리는 측정하지 않았다. 문자만 분석한 시간도
동일한 모델이 이미 올라온 상태의 값이며 문자 전용 경량 패키지 측정이 아니다.
공유 호스트의 반복 wall time이며 독점 하드웨어 벤치마크로 일반화하지 않는다.

관측상 문자 의미 보조가 저비용으로7개를 검토 후보에 올릴 가능성을 보였다.
이미지+문자 조합은 추가1개를 복구할 수 있었지만 CPU 비용이 크다. 따라서 먼저
문자 의미 보조와 기존 공공안내 제외 규칙을 유지한 후보 선별을 별도 자료에서
검증할 가치가 있다. 원본/부분 영역 OCR 개선과 실제 GIF의 읽을 수 있는 프레임 확보도
필요하다. 현장의 섬광 GIF에 대한 이 모델의 추가 효과는 이번 정적 crop 시험으로
확인하지 못했다.

이번 결과만으로 기본 탐지에 모델을 켜거나 Windows 검증을 재개하지 않는다.
실제 정상 광고는 전자제품 판매처2곳의6개에 한정된다. 게임·금융·가상자산 등의
실제 정상 광고, 새로운 광고주/템플릿의 불법 광고, 새로운 공공안내에서 검증해야 한다.
평가와 분리한 자료로 기준을 정하고 이후 별도 검증을 해야 하며, 현재8개에 맞춘
수치 최적화를 독립 성능으로 주장하지 않는다. 제품의 모델 취소/전역 마감/worker
수명/패키징/Windows 네이티브 실행은 NOT_RUN이며 공식 JSON은 변경하지 않았다.

## 실행과 증거

`artifacts/embeddinggemma2-eval-20261021/observed.json`과
`public-guard-composition.json`이 사전 고정/추가 조합을 분리한다.
입력/기준은 `benchmarks/embeddinggemma2/protocol.json`, 재현 방법은 같은 폴더 README다.
baseline JSON, OCR/판정 추적, 모델 해시, 실제 정상 광고 원본, 추론 벡터와 로그를 보관한다.
`validate.mjs`는 입력/기준/기존 결과 해시, 세 계약, 유한한 단위 벡터, 반복 코사인/벡터,
픽셀 변경의 실제 forward 효과를 확인했다. lint·Python 실행·diff 검사도 통과했다.
