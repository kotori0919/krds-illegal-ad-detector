# 저해상도 배너2·GIF1 추가 개선과 비교 검증

2026-10-21. 브랜치 `dev/bootstrap`, HEAD `56fd3563e031ef1850e88b4fdac0c39ead08eea5`.
비교 기준은 직전 작업의 최종 이미지v2/문자v3 실행본이다. 이전 작업 전 실행본을 기준으로 삼지 않았다.

## 결과와 해석

기존 출처 기반 양성55개는 **53→55/55**, 새 실제 양성5개는 **5→5/5**였다.
정상자료74개(실제 공공안내1개 포함)의 오탐은 **0→0/74**였다. 이 수치는 문자 규칙 또는
문자·이미지 **검토 후보**까지 포함한 입력별 탐지이며 법적 위반의 확정이나 OCR 전사 복구율이 아니다.
SMILE/부띠끄의 원문을 보존하면서 이미지로 검토 후보를 회복했다.

별도 파생 GIF3개는 **2→3/3**, 위치 변형4개는 **1→4/4**였다.
새 정상6개 축소본에서 발견된 오탐2개는 최종 **2→0/6**이다. 모든 축소·프레임 재배치·로고 자원은
실제 광고134개와 분리했으며 총190입력 중 별도 대조·자원은56개다.
새 양성5개의 강제 축소 대조본은 **5→4/5**로1개 회귀했다. BUTTER 전체2048px행을137×42로
비균일 변형하면 OCR이 `스포츠해당UP / HE`만 남는다. 숫자·명확한 광고 표현이 없는 일반 제목의
승격을 제한하면서 보류된 경우다. 원본 BUTTER는 전후 탐지됐다. 광고주/스포츠단어 예외나 문구
교정으로 이 대조본을 통과시키지 않았다. 모든 극단 축소를 해결했다는 주장은 하지 않는다.

## 원인과 수정

### 저해상도 두 배너

136–137×41–42의 원본에서 작은 한글 영역은4–8px 높이였다. PP-OCRv5가 영역을 찾아도
확대·보간 뒤 핵심 문구를 일관되게 읽지 못했다. 동일 영역의 PP-OCRv4 및 고정된 bicubic/nearest/
회색/CLAHE 확대도 의미 있는 전사를 충분히 복구하지 못했다. 원시결과는 `diagnosis/regions*.json`,
`scale-observed.json`에 보존했다. 수동 교정·광고주 사전·여러 결과의 문구 합성은 하지 않았다.

기존 이미지v2는 이미지+선택 OCR을 일반 문장 설명과 비교했다. 이미지v3는 같은 FP32
EmbeddingGemma2 체크포인트와 PNG 전처리로 **이미지 질의를 실제 광고 예시 이미지 임베딩과 비교**한다.
이미지 모델에는 추측한 문자나 선택 OCR을 넣지 않는다. OCR은 실제 원문과 대안으로 별도 보존하고
후보 자격·공공/일반 거래 문맥·DOM 중복 확인에 사용한다.

번들 `image-references.json`은 기존 BT8+MT7 양성15개, 정상 참조11개,
그26개의 고정 픽셀 섞기 대조를 포함한52벡터다. 정상 참조의 실제 부모는9개이며 나머지2개는
기존 소매광고 축소본이다. 참조 양성은2개 출처 묶음에서 왔고 현재 두 목표, 이전 이미지 검토3목표,
이번 새 수집은 참조에서 제외했다. 이는 개발자료로 만든 예시 분류기이며 학습내 성능을 독립 정밀도로
해석하지 않는다. 모델 가중치 재학습·새 OCR/Python 런타임·추가 모델 다운로드는 없다.

긍정/부정 최근접 코사인 차이의 기준 **0**과 기존 결정 점수 **3/3**을 유지했다.
원본 차이>=0 **및** seed1701 픽셀 섞기 차이<0이어야 한다. 출처 PNG SHA와 저장 자산을 바인딩하고
실패/취소/마감은 기존 격리 자식에서 처리한다. API의 임의 OCR 문구를 바꿔도 이미지 점수는1e-5내
같으며, 명확한 공공·정상 문맥 제외는 실제 점검 경로에서 우선한다.

| 대상 | 최종 선택 실제 OCR | 원본 차이 | 픽셀 섞기 차이 | 판정 |
|---|---|---:|---:|---|
| SMILE | 8 / 1억95 | +0.019438 | -0.184973 | 이미지 검토 후보 |
| 부띠끄(Boutique) | 0 / 30% | +0.016099 | -0.182658 | 이미지 검토 후보 |

부띠끄의 기존 수집ID `positive-dubai`는 과거 이름이며 화면상 광고주는 부띠끄다.

### 오탐과 정보 보존

단일 출처 예시만 사용한 후보는 정상 쿠폰·게임 광고를 잘못 승격했다. 오탐 예시를 정상 참조에
반영하고 양성 참조의 출처·배치 다양성을 보완했다. 이 실패 자료는 개발자료이며 기각 로그를
최종 측정에 섞지 않았다. 명확히 읽힌 수강/응시료 할인 또는 휴대폰 구매·쿠폰 문맥은 이미지
형태 유사도가 뒤집지 못한다. 실제 카지노 범주나 충전·첫충 등 문맥이 있으면 이 일반 제외를 적용하지 않는다.
광고주 이름/도메인의 허용목록은 없다.

첫 새11실제 입력은 원본 양성5/5·정상 오탐0/6이었지만 균일137×42 축소본2개에서 오탐이 났다.
하나는 OCR이 `2` 한 글자만 남아도 이미지 비교가 허용되던 문제, 다른 하나는 `이달의테택을 한눈에`
같은 일반 제목만으로 문자 의미 모델이 승격하던 문제였다. 이제 한 원문 안에서 %/금액 단위/복수
숫자 그룹이 있어야 이미지 보조로 진행하고, 숫자·실제 광고 표현·offerIntent·전문 표현이 모두 없는
문자 원문은 보류한다. 대안 OCR끼리 합쳐 수치 맥락을 만들지 않는다. 이11실제/11파생은 개발·회귀로 전환했다.

추가 정상3+축소3은 이 보정에 쓰지 않았다. 알려진 운영사의 다른 캠페인이므로 새 운영사나
현장 모집단의 오탐률 검증으로 해석하지 않는다. 이들에서도 오탐은0이었다. 원본3개는 문자 비교를 실행했고 축소3개는 문맥 부족으로
보조 비교에 진입하지 않았다. 이6개는 새 이미지 분류기의 독립 일반화 증거가 아니다.
초기 새 정상 축소6개 중 알라딘1개는 실제 이미지 비교를 실행해 음성이었다.

전체 테스트가 드러낸 연동 회귀도 수정했다. `shouldAnalyzeVisualText`의 보류를 실제 제외로
오인하면 정보가 적은 대안 OCR이 기존 `카지노` 범주를 지웠다. 공공/정상 거래/실제 DOM 중복 제외와
단순 추론 자격 부족을 구분해, 약한 대안은 기존 근거를 보존하고 실제 제외는 우선하도록 했다.

### GIF

기존 코드는 시간4구간마다 경계선 합이 가장 큰 프레임을 선택해, 같은 구간의 줄무늬 장식이
짧은 글자 프레임을 밀어냈다. 현재는128×32 밝기 배치의 최소 쌍별 거리를 우선하는 bounded
다양성 선택을 사용하고 경계선 합은 동률에만 사용한다. 새 프레임이 선택될 때만 PNG를 만들고
인코딩 실패 시 기존 선택을 보존한다. 균일 섬광은 글자 프레임을 밀어내지 않는다.

**4보관/120검사/3초/전체 바이트·OCR 한도는 유지**했다. `bin-competition`의 frame1 자체가
보관·OCR·양성 판정을 받아야 성공으로 세었다. 위치 변형4종의 실제 인코딩 목표 인덱스는0/1/3/4다.
생성기가 중복 장식 프레임을 합치는 점을 반영해 실제 인덱스를 사전 동결했고 목표 RGB가 원본과
같음을 확인했다. 이번 불법 광고주 원본 GIF는 추가 확보하지 못했다. 기존 실제 정상 GIF와 별개로
이7개는 파생 시험이며 모든 실제 애니메이션을 놓치지 않는다는 주장은 없다. 부분 확인 표시는 유지한다.

실제 홍보 자원이다. 이미지/출처/수집시각/해시/crop/파생 규칙과 부정확한 수집의 제외 이유는
`fresh/`와`final-normal/` manifest/fetches에 보존했다. 원본 실제 광고와137×42 파생은 별도 분모다.
실제 광고 목적지가 불명인 소재의 외부 href는 loopback fixture의 통제 조건이며 실제 인프라 증거가 아니다.

최종 **90 점검+워밍2회**, 540 입력 관찰,
문자 비교345/이미지 비교50/대안 기록176를 감사했다.
모든 입력 수집과 선택 프레임 OCR이 완료됐고 optional unavailable0, 공식 JSON의 각 점검 내부
확정 byteidentity/finding0, TS 상세 계약이 통과했다. 394개 소스·입력 해시는 불변이었다.
집중4묶음의 원문/결정은5회 동일, 모델 점수는1e-5 이내였다. 서로 다른 점검의 시간필드까지
공식 JSON이 같다는 주장은 하지 않는다.

`build:scanner`, 웹 빌드, typecheck, lint, **688passed/1skipped**, Linux 공용 Rust **8passed**,
차이 공백 검사가 통과했다. 첫 새 자료의 오탐 및 중간 기각 후보/테스트 실패는 진단 로그로 남겼고
최종 시간·품질 수치에 섞지 않았다. 루트가 코드·경계·원시 결과·집계를 직접 검토했다.
별도 독립 agent 검토, Windows, 패키징/배포/제출/commit/push/PR은 수행하지 않았다.
