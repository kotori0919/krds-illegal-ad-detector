# 공공 웹사이트 불법광고 탐지 도구 기획서

2026년 10월 23일 · 버전 0.2.1

## 1. 배경과 목적

공공기관 웹사이트의 게시글·댓글·삽입 프레임에는 투명한 글자, 화면 밖 문구,
분해 자모와 닮은꼴 문자를 이용한 광고가 숨어들 수 있다. 육안 점검은 보이지 않는
요소를 놓치고, 단순 문자열 검색은 변형된 표기를 놓친다. 발견 목록만으로는
담당자가 시정 요청의 근거와 확인하지 못한 범위를 설명하기 어렵다.

본 도구는 **주소 입력 → 점검 → 근거 검토 → 판단·메모 → 보고서**를 하나의
업무 흐름으로 연결한다. 비전문 담당자가 무엇이 어디에 어떻게 숨어 있었는지
확인하고, 후속 조치에 필요한 기록을 남기는 것이 목적이다.

| 목표 | 제공하는 결과 |
| --- | --- |
| 일정한 기준의 반복 점검 | 하위 페이지·프레임을 예산 안에서 확인하고 네 가지 공식 은폐 기법 판별 |
| 근거를 읽고 판단 | 원문·페이지·관측 위치·이유·화면 근거와 담당자 판단·메모 |
| 확인 범위가 드러나는 보고 | 확인·실패 페이지와 상한을 남기는 공식 JSON 및 업무용 XLSX |

목표 환경은 Windows 11, 4~6코어, 8GB 메모리, GPU 없는 일반 업무용 PC다.
공식 판정과 OCR·임베딩을 로컬 CPU에서 실행하고 점검 내용을 외부 AI 서비스에
전송하지 않는다.

## 2. 사용자와 업무 흐름

### 점검 설정 → 사이트 점검 → 결과 검토

1. **점검 설정**: 주소와 연결 방식·점검 범위를 확인하고 시작한다. 간단 모드는
   최대 200페이지·하위 4단계·25분을 기본 범위로 안내한다.
2. **사이트 점검**: 경과 시간, 확인 페이지, 실패 페이지와 탐지 수를 보여 준다.
   전체 탐색량을 알 수 없으면 임의 백분율을 만들지 않는다.
3. **결과 검토**: 발견 문구와 페이지를 검색하고 근거를 연다. 원문·관측 위치·
   자연어 이유를 확인한 뒤 판단과 메모를 저장한다.
4. **보고서 저장**: 검토 기록을 반영한 XLSX와 공식 JSON을 내보낸다.

간단 모드는 주소 입력과 검토·보고에 집중하고, 고급 모드는 세부 범위와 일괄
가져오기·점검 범위·인프라 분석을 제공한다. 두 모드는 같은 탐지 엔진과 저장소를
공유한다.

여러 사이트는 CSV·XLSX·JSONL·XML 목록의 오류·중복·유효 대상을 먼저 확인한다.
사이트별로 순차 실행하며 각 대상의 공식 결과와 케이스 번호를 독립 보관한다.
업무용 통합 XLSX에는 대상 요약이 추가된다.

## 3. 데이터와 판정 기술

### 은폐와 광고를 나누는 두 축 판정

공식 탐지는 은폐 기법 근거와 광고 의미 근거가 모두 성립할 때 생성한다.
접힌 메뉴·스크린리더용 문구·정상 애니메이션 같은 숨김과 신고·예방·교육 문맥을
구분한다.

| 공식 기법 | 처리 방식 |
| --- | --- |
| HOMOGLYPH | 전각·키릴/라틴 유사자·일부 리트 표기·단어 안 구두점을 정규화 |
| JAMO | 유니코드 한글 조합 규칙으로 분해 자모 복원 |
| TRANSPARENT | 요소와 조상의 계산 스타일로 투명·은닉 상태 확인 |
| OFFSCREEN | 위치·크기·잘림과 조상 상태로 화면 밖 은닉 확인 |

원문은 보존하고 정규화·OCR·모델 유래 표현은 별도로 남긴다. 위치는 선택자의
유일성과 왕복을 확인하며 iframe 경로를 함께 기록한다.

### 필요한 후보에만 이미지 분석

광고 표식 또는 외부 목적지가 있는 이미지부터 수집한다. Tesseract 한국어·영어를
먼저 적용하고 저신뢰 PNG에는 PP-OCRv5 CPU 모델을 사용한다. 규칙으로 해결하지
못한 일부 배너만 고정 문자·이미지 임베딩과 비교한다. 정상 상품 광고와 공공 안내
문맥을 먼저 걸러내며, 문서당 32후보·서로 다른 OCR 입력 40개 등 단계별 상한을 둔다.

합성 자료는 22케이스(양성 13·음성 7·구조 2), 기대 판정 17쌍으로 구성된다.
네 기법과 정상 숨김, 중첩 iframe, 지연 삽입, 쿼리 값이 다른 게시판을 포함한다.
확보한 실제 소재 190입력·29묶음은 이미지 광고의 회귀 평가에 사용한다.

### 추가 탐지

공식 네 기법과 구분하여 이미지 전용 광고, 재사용 크리에이티브, 광고 인프라 상관,
제로폭 위장 단서를 제공한다. 추가 단서를 공식 건수에 더하지 않아 담당자가
근거의 종류와 의미를 구분할 수 있다.

## 4. 아키텍처와 구현

| 구성 | 책임 |
| --- | --- |
| React + Vite | 점검 설정, 진행·결과 화면, 근거 검토, 판단·메모, 보고서 동작 |
| typed HostBridge | 화면과 네이티브 기능 사이의 명시적 인터페이스 |
| Tauri 2 / Rust | 세션과 자식 프로세스 소유, 취소·종료, 원자적 케이스 저장·검토 리비전 |
| Node / Playwright | 동일 사이트 BFS, DOM·프레임 수집, 기법·광고 판정, 구조화 결과 생성 |
| 로컬 분석 자식 | CPU OCR·임베딩과 개별 분석 예산 관리 |

페이지·전체 점검은 하나의 단조 증가 마감 기준을 공유한다. JavaScript 문서 이동을
추적하고 준비 중 전환을 최대 2회로 제한한다. 진입 호스트·포트 밖으로 이동하면
외부 이동으로 기록하고, 접근 제한·시간 초과와 구분한다. URL의 쿼리 값은 서로 다른
페이지일 수 있으므로 보존한다.

Windows Job Object로 워커·브라우저·렌더러 트리를 묶어 취소·시간 초과·앱 종료 시
함께 정리한다. 공식 결과를 검증해 먼저 확정하고, 선택적 근거 단계와 검토 기록은
별도로 저장한다. 모델과 언어 데이터는 빌드 때 고정해 설치본에 포함한다.

## 5. 증거·결과 관리 UI

결과 화면은 목록과 근거 패널을 나란히 배치한다. 상세는 발견 문구 → 페이지와 위치
→ 자연어 이유 → 촬영·OCR 근거 → 담당자 판단과 메모 순서로 구성한다. 선택자·
iframe 경로·계산된 스타일·기하 값은 접힌 기술 정보로 제공한다.

검색·필터·선택 맥락을 유지하고 반복 항목·페이지별·전체 기록으로 결과를 탐색한다.
점검 범위에서는 확인·실패 페이지, 실패 이유와 수집·분석 상한을 보여 준다.
인프라 분석은 저장한 근거의 도메인·페이지·관계를 역추적한다.

| 저장 단위 | 역할 |
| --- | --- |
| 공식 JSON | 원문·위치·기법·판정을 검증해 보존 |
| 추가 분석 | 이미지 광고와 반복·상관 단서를 별도 보관 |
| 검토 기록 | 읽음 상태·담당자 판단·메모를 공식 원본과 분리해 자동 저장 |
| XLSX | 점검 요약·탐지 상세·범위·추가 분석·검토 기록, 여러 대상의 대상 요약 |

보고서는 검토 저장을 확인한 뒤 생성한다. 원문과 메모는 문자열 셀로 기록해 수식으로
해석되지 않게 한다. 저장 케이스를 다시 열어 검토와 보고서 작성을 이어갈 수 있다.

## 6. 실제 배포와 운영

Windows NSIS 설치본에 Node, 브라우저, OCR 언어 데이터와 모델을 포함한다. 설치 후
개발 저장소나 개발 도구를 요구하지 않는다. 케이스와 검토 기록은 로컬 사용자
영역에 저장한다. 설치 파일 크기는 712.36MiB다.

기본 연결은 현재 PC 네트워크를 사용한다. 고급 설정에서는 앱 전용 WARP를 점검
단위로 선택할 수 있다. 연결 준비를 확인한 뒤 점검하고, 시스템 DNS·전역 경로는
변경하지 않는다.

기본 점검 예산은 1,500초, 내부 정지는 1,650초, 공식 상한은 1,800초다.
목표 환경의 기본 동시성은 2이며 페이지·깊이·시간을 함께 제한한다.

Windows 11 VM(4 논리 CPU·8GiB·GPU 없음)의 패키지 워커로 실행한 200페이지 생성
시나리오는 모든 동시성에서 199페이지 확인·의도적 실패 1개, TP21/FP0/FN0을 기록했다
(2026-10-07, source `1b0611d`). 전체 공식 결과와 실패 목록은 동시성 간 동일했다.

| 워커 수 | 소요 시간 | 기준선 대비 피크 메모리 |
| ---: | ---: | ---: |
| 1 | 347.131초 | 425.4MiB |
| 2 | 174.271초 | 433.1MiB |
| 3 | 112.477초 | 537.5MiB |
| 4 | 87.849초 | 781.9MiB |

각 수준의 단일 실행이며 최신 이미지 분석의 종합 성능과 구분한다.

## 8. 기대 행정 효과와 독창성

담당자가 바뀌어도 발견 위치·원문·검토 판단·시정 요청을 이어갈 수 있다. 정기 점검과
보고서 작성의 기준을 통일하고, 대상별 점검 기록을 다시 확인할 수 있다. 확인하지 못한
범위를 함께 남겨 후속 점검의 우선순위를 정하는 데 활용한다.

1. **은폐와 광고의 두 축 판정**으로 정상 숨김과 변형 광고를 구분한다.
2. **위치의 재현성**으로 담당자와 유지보수자가 같은 요소를 확인한다.
3. **비용 사다리**로 필요한 후보에만 OCR·임베딩을 사용해 CPU 환경에 맞춘다.
4. **원본과 사람 판단을 분리**해 공식 결과를 보존하면서 검토 기록을 축적한다.
5. **같은 엔진의 두 화면 모드**로 비전문 담당자와 고급 점검자의 작업을 함께 지원한다.

이미지·로고·애니메이션 인식 범위와 기관의 실제 검토 자료를 확장하는 것이 다음
발전 방향이다. 반복 크리에이티브와 광고 인프라 관계를 활용해 후속 점검을 지원한다.
