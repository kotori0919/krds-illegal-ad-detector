# 기획서 — 공공 웹사이트 불법광고 탐지 도구

공모전 제출용 기획·지원 문서. 2026-10-22 현재 소스와 실행 기록을 기준으로 작성했다.
이전 2026-10-05 초안은 당시 목표 설계를 서술했으며, 본 문서가 이를 대체한다.

## 0. 문서 기준과 상태 구분

이 문서는 다음 세 가지를 섞지 않는다.

| 구분 | 뜻 | 현재 상태 |
| --- | --- | --- |
| 구현 완료 | 저장소 소스에 존재하고 자동 시험이 통과하는 기능 | 2026-10-22 소스 기준 |
| Windows 실제 검증 | Windows 11 설치본에서 사람이 조작해 관측한 결과 | 2026-10-09 빌드(후보 565)까지 |
| 미실행 | 설계·소스만 있고 실제 실행 기록이 없는 항목 | 아래 12절 참조 |

가장 중요한 구분은 다음과 같다. **WARP 전송과 간단·고급 모드가 포함된 최신 소스
`85a286f`은 Windows용 설치 후보로 만들어 검증했지만, Windows에서 설치·조작해 관측한
기록은 아직 없다.** 2026-10-23 Linux 교차 빌드(`x86_64-pc-windows-gnullvm`)로 만든
서명 없는 NSIS 후보(759.46 MiB, sha256 `54c8f1cd…df406`)는 artifact verify를 통과했다.
이 후보는 Tauri가 "실험적"으로 표시하는 교차 컴파일 산출물이며 MSVC 배포 경로가 아니다.
Windows MSVC CI와 실제 설치·화면 수용, WebView2 부재 offline 설치는 NOT_RUN이다(CI는
계정 결제 차단으로 job이 시작되지 않았다). Windows에서 마지막으로 관측된 것은 2026-10-09

그 이후의 화면·전송·탐지 변경은 설치본 동작으로 검증된 것이 아니다
(ADOPTION_HANDOFF_KO.md, 2026-10-10; DOGFOOD_LEDGER_20261014.md, 2026-10-14;
ADOPTION_LEDGER.md 2026-10-23 절).

기능 판정은 "구현됨"과 "검증됨"을 구분해 서술한다. 제출 준비 완료를 뜻하는 문구는
쓰지 않는다. 2026-10-22 Linux 개발기에서 전체 시험은 703 passed/1 skipped(95파일)였고
scanner·web 빌드, typecheck, lint가 통과했다(VISION_CPU_OPTIMIZATION_20261022.md).
이 결과는 Windows 설치본 동작을 검증하지 않는다.

## 1. 배경과 문제

지방자치단체와 공공기관 웹사이트는 시민이 가장 먼저 접하는 행정 창구다. 그런데
공공 사이트의 게시글·댓글·첨부 이미지·삽입 프레임에는 도박, 불법 대출, 현금화
같은 광고가 숨어 들어온다. 문제는 이 광고들이 **정상 화면에 보이지 않는다**는
점이다. 글자 색을 배경과 같게 만들거나, 투명도를 0으로 두거나, 화면 밖으로
수 킬로픽셀 밀어내거나, 한글 자모를 분해하거나, 키릴 문자·전각 문자로 모양만
흉내 내는 방식으로 사람의 눈과 단순 문자열 검색을 동시에 피한다.

현장 점검 방식은 이 문제에 구조적으로 취약하다.

- 육안 점검은 보이는 화면을 본다. `display:none` 안에 들어 있는 문장은 보이지
  않으므로 "확인했다"고 말할 수 없지만, 그렇다고 "없다"고 말할 수도 없다.
- 문자열 검색은 원문을 그대로 찾는다. `ㅋㅏㅈㅣㄴㅗ`, `ＣＡＳＩＮＯ`, `카.지.노`
  처럼 변형된 표기를 놓친다.
- 외주 점검은 비용과 주기가 있어 정기 점검이 어렵고, 결과물이 "발견 목록"으로
  끝나 근거·판정·후속 조치가 분리된다.
- 담당자는 대부분 웹 개발자가 아니다. HTML·CSS·선택자·모델 점수를 읽을 수 있는
  도구는 실제 업무에 쓰이지 않는다.

따라서 필요한 것은 탐지율 숫자 하나가 아니라, **비전문 담당자가 한 번의 점검으로
"무엇이 어디에 어떻게 숨어 있었고, 어디까지 확인했고, 무엇을 확인하지 못했는지"를
설명할 수 있는 산출물**이다. 본 과제는 이 지점을 제품 요구사항으로 삼았다.

## 2. 목적

목표는 다음과 같이 정의했다.

1. 공공 웹사이트 주소 하나를 입력하면 하위 페이지·게시글·댓글·삽입 프레임을
   자동으로 수집하고, 네 가지 공식 은폐 기법을 판별한다.
2. 판별 결과를 **원문·페이지 주소·선택자·실제 화면 근거**와 함께 남겨, 담당자가
   개발 지식 없이도 "왜 이것이 탐지되었는지" 확인할 수 있게 한다.
3. 확인하지 못한 페이지(접근 실패·시간 초과·수집 상한)를 성공 결과와 분리해
   표시한다. 탐지 0건을 "안전"으로 해석하지 않도록 화면 문구와 보고서 양쪽에서
   못박는다.
4. 결과를 공식 JSON과 업무용 엑셀 보고서로 남기고, 담당자의 판단·메모를 원본과
   분리해 보관한다.
5. 이 모든 것을 Windows 11, GPU 없는 일반 PC에서 수행하고, 공식 판정 경로는 외부
   AI 서비스에 접속할 수 없는 환경에서도 동작하게 한다(KODEX.md §28, 2026-10-01).
   점검 대상 사이트에 접속하는 네트워크는 별개이며, 오프라인 보장은 AI·모델
   의존성에 대한 것이다.

평가 환경은 Windows 11, 4~6코어, 8GB 메모리, GPU 없음, 30분 제한을 전제로 한다
(KODEX.md §29; PRODUCT_SPEC.md, 2026-10-20). 기본 점검 예산은 1500초다.

## 3. 데이터와 기술

### 3.1 데이터

- **합성 평가 사이트**: 22개 케이스(양성 13, 음성 7, 구조 2), 기대 판정 쌍 17개.
  양성은 네 기법별 은폐 예제와 한 요소에 두 기법이 겹친 복합 사례를 포함한다.
  음성은 sr-only 링크, 숨긴 내비게이션, 반응형 안내문, 정상 자모·유니코드
  사용례다. 구조 케이스는 중첩 iframe, 쿼리 값이 다른 게시판, 지연 삽입 광고,
  중복 URL을 다룬다(SYNTHETIC_EVAL.md, 2026-10-01).
- **적대적 표본**: 키릴·라틴 혼용, 구두점 분리, 숫자 치환, 자모 혼합, 조상
  투명도, 오프스크린 변환, clip-path, overflow 은닉의 8개 공격 유형이 모두
  발화(FIRES)로 관측됐다(ADVERSARIAL.md, 2026-10-01).
- **실제 소재**: 언론 보도 화면과 저장한 웹툰 사이트 화면에서 잘라낸 실제 불법
  배너, 실제 정상 광고, 공공 안내 이미지. 2026-10-22 기준 190개 입력/29묶음이
  회귀 측정에 사용되고 그 원시 기록이 보존되어 있다
  (EMBEDDING_QUANTIZATION_20261022.md).

실제 소재는 공개 사이트에 다시 접속해 수집한 것이 아니라, 확보해 둔 화면·이미지를
소유한 loopback 페이지에서 재생해 측정한다. 이는 현장 재현이 아니라 회귀 검증이다.

### 3.2 판정 구조: 2축 결정

공식 판정은 두 축이 모두 성립할 때만 만들어진다(DETECTION.md, 2026-10-01 동결).

```text
기법 근거(TechniqueEvidence) + 광고 근거(IllegalAdEvidence)
  → 후보 근거(CandidateEvidence) → 결정 근거(DecisionEvidence) → 공식 탐지
```

- **A축(은폐 기법)**: HOMOGLYPH(닮은꼴 글자 위장), JAMO(자모 분해),
  TRANSPARENT(투명 텍스트), OFFSCREEN(화면 밖 은닉).
- **B축(광고 의미)**: `text-policy-2`. 강한 광고·불법 범주어, 또는 일반어에
  구체적 제안 의도가 붙은 경우, 또는 의심스러운 광고 목적지가 있어야 성립한다.
  `보장`·`당일`·`고액`·`보너스`·`쿠폰`·`무료체험`만으로는 광고로 보지 않는다.

이 구조가 중요한 이유는 **은폐 자체를 위반으로 보지 않기 때문**이다. 접힌
내비게이션, 스크린리더용 텍스트, 애니메이션의 `opacity:0` 상태는 정상 웹 구현이다.
따라서 "숨겨져 있으면 탐지"라는 규칙은 쓰지 않는다. 또한 신고·예방·교육·통계·
접근성 안내 문맥은 불법 행위를 언급해도 광고로 판정하지 않는다. 반대로 같은
페이지의 다른 댓글이 실제 광고라면 그 요소는 별도로 판정된다.

애매한 경우는 결정 모델이 보조하지만, 모델이 단독 탐지기가 되지는 않는다.
결정 근거에는 적용 규칙·점수·임계값·통과 여부가 함께 남는다.

### 3.3 텍스트 정규화와 위치 특정

- HOMOGLYPH는 전각 문자, 매칭용 ASCII 대소문자 폴딩, UTS #39 15.1.0 기준
  키릴·라틴 유사자, 매칭어 내부 구두점, 완전한 라틴 `casino` 리트 표기를
  처리한다. 날짜·전화번호의 숫자를 전역 치환하지 않는다. 지원 범위는
  `text-policy.ts`에 고정되어 있고, 지원하지 않는 유사자는 재현율 한계로
  남긴다.
- JAMO는 유니코드 한글 조합 공식을 따라 자모를 음절로 복원한다. `ㄷㅐㅊㅜㄹ` →
  `대출`처럼 호환 자모를 종성으로 쓰는 경우도 포함한다. 자음만 이어진 웃음
  표현, 분해된 고유명사는 발화하지 않는다.
- 원문은 절대 덮어쓰지 않는다. `evidence_text`는 정규화 이전 원문을 그대로
  보존하고, 복원·OCR·모델 유래 표현은 별도 필드에 둔다. 각 변형 구간은 원문의
  UTF-16 오프셋으로 역추적된다(서로게이트 쌍 포함).
- 위치는 결정적 선택자 생성기로 만들고, 실제 문서에서 유일성과 왕복을 검증한다.
  iframe 내부는 `>>>`로 직렬화한다. 선택자 유일성 검증에 실패하면 결과 저장이
  차단된다.

### 3.4 이미지 분석: 3단계 게이트

이미지 광고는 DOM 문자열이 없으므로 별도 경로를 쓴다. 비용이 큰 순서대로
단계를 두고, 앞 단계가 통과한 후보만 다음 단계로 넘긴다.

1. **수집**: 광고 표식이 있는 요소, 또는 외부 HTTP(S) 목적지로 연결된 이미지만
   후보가 된다. 문서당 최대 32후보, 페이지당 인코딩 1,000,000바이트, 개별
   원본·변환 이미지 250,000바이트, 서로 다른 OCR 입력 40개, 보관 자산
   40개·2,000,000바이트(`packages/contracts/src/policy.json`의 `visual` 절;
   DETECTION.md, 2026-10-21).
2. **문자 인식**: 선명한 이미지는 Tesseract 한국어·영어가 먼저 처리한다.
   신뢰도가 낮은 PNG는 고정 PP-OCRv5 mobile 검출·한국어 인식을 CPU
   onnxruntime으로 수행한다. 모델은 빌드 시 SHA-256·크기로 검증해 패키지에
   포함하며, 점검 중 내려받지 않고 이미지를 외부로 보내지 않는다. 네이티브
   추론은 별도 자식 프로세스가 맡아, 마감 초과 시 부모 스캐너를 죽이지 않고
   자식만 종료할 수 있다(ADR-0017, 2026-10-21).
3. **의미·이미지 비교**: 규칙으로 판정하지 못한 외부 연결 배너에 한해,
   문자 전용 임베딩(EmbeddingGemma 2 텍스트, CPU FP32, 2스레드)이 고정
   한·영 참조 문장과 비교한다. 더 나아가 미해결 저해상도 PNG(높이 96 이하,
   가로세로비 3 이상)는 같은 체크포인트의 이미지 인코더(8비트 가중치)로 실제
   픽셀을 참조 이미지와 비교한다. 공공 안내·일반 거래·같은 화면 본문 중복은
   제외 규칙으로 먼저 걸러낸다.

세 번째 단계의 결과는 **검토 후보**이지 문자 복원도, 법적 위반 확정도 아니다.
유사도 점수는 확률로 표시하지 않는다.

선택적 학습 VLM은 현재 비활성화되어 있다. 이미지 판정에 쓰이는 것은 위의 고정
체크포인트 임베딩이며, VLM이 켜져 있다는 전제로 화면이나 문서를 쓰지 않는다
(USER_MANUAL.md, 2026-10-20).

### 3.5 비용 정책

- 파이프라인 순서는 URL → DOM 추출 → 유니코드 → 계산 스타일 → 기하 → 프레임 →
  네트워크·자원 → 이미지 지문 → 게이트된 OCR → 구조화 판정 → 선택적 보조
  모델이다. 모든 요소에 스크린샷을 찍거나 모든 이미지에 OCR을 돌리지 않는다.
- 수집 상한: 텍스트 노드 10,000, 소유자 1,000, 전체 원문 1,048,576 코드 유닛,
  소유자당 32,768, 스타일 하위 요소 32개. 프레임 깊이 기본 4, 페이지당 자식
  프레임 15개(DETECTION.md, 2026-10-01).
- GIF는 ImageDecoder로 최대 120프레임을 3초 안에서 살피고, 128×32 서명과
  대비 순위로 최대 4프레임을 남긴다. 선택하지 못한 구간은 "부분 분석"으로
  기록한다. APNG·애니메이션 WebP·동영상은 대상이 아니다.

```text
React + Vite (apps/web)
  └─ typed HostBridge (packages/contracts/src/host.ts)
       ├─ BrowserHost  : 예시 데이터 미리보기
       └─ TauriHost    : 26개 IPC 명령 + scan-event 구독
            └─ Tauri 2 호스트 (src-tauri, Rust)

                 └─ Node 스캐너 사이드카 (packages/detection/src/worker.ts)
                      └─ Playwright → 수집 → 탐지 → 결과 엔진 → JSON
```

설계 원칙은 세 가지다.

- **얇은 호스트**: `src-tauri/src/main.rs`의 `generate_handler`에 등록된 IPC
  명령은 26개다. 기능별로 묶으면 다음과 같고, 화면은 typed HostBridge를 통해
  이들만 호출하며 `scan-event`를 구독한다.

  | 묶음 | 명령 |
  | --- | --- |
  | WARP 설정(3) | `get_warp_status`, `open_warp_terms`, `register_warp` |
  | 점검 수명주기(3) | `scan_start`, `scan_cancel`, `scan_get_session` |
  | 일괄 점검(1) | `scan_start_batch` |
  | 결과 읽기(2) | `scan_get_result`, `scan_get_extra_result` |
  | 상세·근거 읽기(6) | `scan_get_coverage`, `scan_get_finding_detail`, `scan_get_image_analysis`, `scan_get_evidence_asset`, `scan_get_evidence_summary`, `scan_get_evidence_graph_slice` |
  | 내보내기·양식(4) | `scan_export`, `scan_export_workbook`, `scan_export_batch`, `scan_save_template` |
  | 사례 저장소(6) | `case_list`, `case_open`, `case_save_review`, `case_export`, `case_import`, `case_delete` |
  | 진단(1) | `support_diagnostics` |

  셸 실행 명령은 없다. `src-tauri/Cargo.toml`에 셸 플러그인이 없고,
  `src-tauri/capabilities/default.json`이 허용하는 권한은 `core:default`,
  `core:event:default`, `core:window:allow-destroy`, `dialog:allow-open`,
  `dialog:allow-save`, `fs:allow-write-text-file`뿐이다. 클라이언트는 스캔
  파라미터만 전달하며 셸 문자열을 넘기는 경로가 없다. CSP도
  `default-src 'self'; script-src 'self'`로 고정되어 있다(tauri.conf.json).
- **소유권 경계**: 사이드카 자식 PID를 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`
  (0x2000) 하나만 설정한 Job Object에 붙인다(`src-tauri/src/job.rs`). 세션
  guard가 드롭되면 워커→브라우저→렌더러 트리가 함께 종료되며, 취소·비정상
  종료·시간 초과·앱 종료가 같은 Drop 경로로 수렴한다. 호스트 프로세스는 Job에
  넣지 않는다. POSIX 빌드는 `kill_on_drop`으로 같은 정리를 수행한다.
- **공식 원본 불변**: 공식 JSON은 선택적 근거·OCR·그래프보다 먼저 확정된다.
  이후 단계가 실패해도 이미 확정된 공식 결과를 무효화하지 않는다
  (CONTRACTS.md). 원본·검토·진단 데이터는 `result.json`, `result_extra.json`,
  `review.json`으로 분리한다(DATA_HANDLING_KO.md).

두 실행 모드(간단·고급)는 같은 탐지 엔진·케이스 저장소·검토 writer를 공유한다.
화면 구성만 다르며, 같은 조건에서 모드가 탐지 결과를 바꾸지 않는다(ADR-0016,
2026-10-20).

## 5. 구현

### 5.1 탐지 엔진과 수집기

- 크롤러는 Playwright API로 동일 사이트 BFS를 수행하고, URL 정규화(후행 슬래시·
  프래그먼트·쿼리 순서)로 중복을 제거한다. 쿼리 **값**은 보존한다. 다른 값은
  다른 페이지일 수 있기 때문이다.
- 메인 프레임 리다이렉트는 진입 호스트(포트 포함)를 벗어나면 본문을 분석하지
  않고 `external-redirect` 실패로 기록한다. 외부 iframe은 원래 프레임 URL과
  선택자 체인으로 관측하되 사이트 페이지로 재귀 수집하지 않는다.
- 페이지 처리는 단일 패스이며, 하나의 단조 증가 마감 시각을 모든 페이지가
  공유한다. 동시성은 1~4 범위이고 4-vCPU/8GB 환경의 기본값은 2다
  (PRODUCT_SPEC.md, 2026-10-20).

### 5.2 증거 수집

- **증거 그래프**: Page/Frame/Element/Resource/Creative/Domain/Redirect/Landing
  노드와 CONTAINS/LOADS/EMBEDS/DISPLAYS/LINKS_TO/REDIRECTS_TO/SIMILAR_TO 간선.
  서술 규칙은 "상관·공유·반복 관측"이며, WHOIS·CDN·지리 정보로 운영자 신원을
  단정하지 않는다(DETECTION.md §8).
- **크리에이티브 지문**: 공식 탐지 이후 이미지 응답 바이트와 라이브 페이지의
  8×8 픽셀 표본으로 지문을 만든다. 추가 요청·이동을 만들지 않는다.
- **화면 근거**: 탐지 요소의 실제 JPEG 크롭을 세션 범위 자산으로 보관하고,
  호스트를 통해 읽는다. 페이지가 임의 파일 경로를 지정하게 두지 않는다.

### 5.3 결과·검토·보고서

- 공식 결과는 저장 전 검증을 통과해야 한다: JSON 파싱 가능, UTF-8 BOM 없음,
  `meta` 필수값, 판정 필수 필드, ID 유일성, 기법 값이 공식 4종인지, 중복 식별
  (`url+location+technique`), URL 형식, 선택자 유일성·왕복. 하나라도 실패하면
  저장이 차단된다(DETECTION.md §10).
- 검토 기록은 원본과 분리된 `review.json`에 저장한다. 읽음 상태(검토 완료),
  담당자 판단(판단 전·광고 의심·정상으로 판단·추가 확인 필요), 메모를 자동
  저장하며, 저장 실패 시 편집 내용을 유지하고 재시도를 제공한다. 원본 탐지
  수와 `is_violation`은 바뀌지 않는다.
- 엑셀 보고서는 점검 요약, 반복 항목, 탐지 상세, 페이지·점검 범위, 추가 분석,
  검토 기록 시트로 구성되고, 여러 대상이면 대상 요약 시트가 추가된다
  (`packages/evidence/src/report.ts`). 원문과 메모는 문자열 셀로 기록하며 수식·
  외부 링크로 해석되지 않는다. 보고서 생성 전에 검토 저장 완료를 확인한다.

### 5.4 연결 방식

- **기본 연결**은 현재 PC 네트워크를 사용한다. WARP 등록·설정 파일이 없어도,
  설정이 손상돼도 일반 점검을 시작할 수 있다.
- **앱 전용 WARP**는 고급 모드의 연결 설정에서 사용자가 약관에 동의하고 등록을
  실행한 뒤, 점검 단위로 선택했을 때만 사용한다. 등록 완료는 "등록됨 · 점검
  시작 시 연결"이며 연결 중이 아니다. 점검마다 usque 4.2.1 고정 실행 파일을
  자식 프로세스로 띄우고, 인증된 loopback 프록시와 고정 HTTPS trace의 `warp=on`
  을 확인한 뒤에만 진행한다. 준비 시간도 점검 마감에 포함된다.
- 실패 시 직접 연결로 자동 전환하지 않는다. 연결 방식을 바꿔 다시 점검하면 새
  케이스를 만들고 이전 케이스를 보존한다. 공식 WARP 클라이언트·시스템 DNS·
  전역 경로는 변경하지 않는다(WARP_REGISTRATION.md; DESKTOP.md "Worker WARP
  transport").

## 6. 사용자 흐름

화면 단계는 세 개다: **점검 설정 → 사이트 점검 → 결과 검토**
(`apps/web/src/steps.ts`). 근거 확인·내보내기·범위 확인은 결과 단계 안의
동작이며 별도 단계가 아니다. 첫 실행에서는 "어떤 방식으로 사용하시겠습니까?"에서
간단 모드(기본) 또는 고급 모드를 고른다. 선택은 기기 환경설정에 저장되고,
이후 상단 메뉴에서 바꿀 수 있다.

### 간단 모드

1. **새 점검**: 주소를 입력하고 최대 200페이지·하위 4단계·최대 25분, 기본 연결
   사용 중임을 확인한 뒤 점검을 시작한다.
2. **사이트 점검**: 경과 시간, 확인한 페이지, 기본 탐지, 확인하지 못한 페이지
   수를 본다. 총 탐색량을 모르므로 백분율을 만들지 않는다. 중지는 확인 후
   호스트의 종료 상태를 기다린다.
3. **결과 검토**: 의심 항목 목록에서 문구·페이지를 검색하고 검토 상태로
   좁힌다. 항목을 열면 원문·촬영 근거·이유가 나오고, 판단과 메모를 입력한 뒤
   "검토 완료·다음"으로 넘어간다. 읽음 완료는 위반 확정이 아니다.
4. **보고서 저장**: 검토 기록 저장을 먼저 완료하고 엑셀 보고서를 생성해 native
   저장 대화상자를 연다. 평가용 JSON은 "결과 파일" 보조 메뉴에서 저장한다.

간단 모드에는 빠른 점검·깊이 입력·OCR 설정·그래프·일괄 가져오기 버튼을 두지
않는다. 비전문 담당자가 매번 설정을 해석하지 않아도 되게 하기 위해서다.

### 고급 모드

한 사이트 또는 여러 사이트를 점검한다. 여러 사이트는 CSV·XLSX·JSONL·XML
대상 목록을 미리 확인(오류·중복 표시)한 뒤 사이트별로 순차 실행하고, 대상마다
공식 결과를 따로 보관한다. 사이트별 공식 JSON을 하나의 공식 결과로 합치지
않는다. 진행 화면은 작업 페이지·대기열·분석 요소·최근 활동을 접어서 제공한다.
결과 화면은 `탐지 항목 | 점검 범위 | 인프라 분석` 세 영역을 가진다.

### 상태와 복구

주소 오류는 입력을 유지하고 첫 오류로 포커스를 옮긴다. 일부 실패·시간 만료는
보관된 유효 결과를 검토하게 하고 보고서에도 범위 제한을 남긴다. 근거가 없으면
없는 이유를, 분석 상한에 걸렸으면 상한을 표시한다. 탐지 0건은 "확인 범위와 함께
관측 0건"으로 표현하며 안전을 보증하지 않는다.

## 7. 증거·결과 관리 UI

이 제품의 핵심 차별점은 탐지 개수가 아니라 **결과를 읽고 판단하는 작업면**이다.
데스크톱에서는 목록과 근거 패널을 나란히 두고, 좁은 화면에서는 전체 폭 상세로
연다. 상세의 내용 순서는 다음과 같다.

1. 발견 문구 또는 이미지 (원문은 선택·복사 가능)
2. 발견 페이지 주소와 관측 위치
3. 자연어로 쓴 이유 ("왜 이 요소가 은폐 광고로 판단됐는지")
4. 실제 촬영 근거(JPEG 크롭)와, 있을 경우 OCR 원문·대체 인식 결과·프레임 시각
5. 담당자 판단과 메모
6. 접힌 기술 정보: 선택자, iframe 경로, 계산된 CSS, 기하 값

설계상 지켜지는 규칙은 다음과 같다.

- **공식 탐지와 추가 분석을 섞지 않는다.** 추가 단서는 별도 수와 별도 목록으로
  항상 보이게 하고, 공식 건수에 더하지 않는다. 기본 0건·추가 2건인 결과를
  "탐지 결과 없음" 한 문장으로 덮지 않는다.
- **점검 범위를 별도 화면으로 둔다.** 확인한 페이지, 실패한 페이지와 이유,
  수집·이미지 분석 상한을 보여 준다. 전체 미방문 페이지 수를 모르면 "알 수
  없음"으로 표시한다. 파일을 못 읽은 상태와 관측 0건을 구분한다.
- **검색·필터 문맥을 유지한다.** 항목을 오가도 검색어·필터·선택 행·스크롤이
  초기화되지 않는다. 선택 항목이 필터에서 제외되면 근거 패널을 닫고 이유를
  알린다.
- **인프라 분석은 저장 근거만 읽는다.** 현재 또는 선택한 저장 케이스 하나의
  광고 연관 도메인을 검색·필터하고, 행을 선택하면 관련 페이지와 원본 기록으로
  역추적한다. 상단에 "저장 근거 분석 · 외부 사이트에 새로 접속하지 않음"과
  분석 제한을 표시한다. 일반 CDN·폰트·분석 도구를 단순 포함만으로 목록에
  넣지 않고, 관측 역할은 저장 그래프의 노드·간선이 뒷받침할 때만 표시한다.
  여러 케이스 통합과 능동 외부 탐색은 제공하지 않는다.
- **외부 목적지를 자동으로 열지 않는다.** 주소 복사와 명시적 열기를 분리하고,
  열기는 안전한 `http(s)` 이동만 허용한다.

## 8. 실제 배포 — Windows 11, 무GPU, 오프라인 공식 경로

### 8.1 배포 형태

Tauri 2 기반 NSIS 설치 파일 하나로 배포한다. 설치 후 Node, 개발 저장소,
별도 Playwright·OCR 모델 설치가 필요 없다. 앱 식별자는
`kr.go.nia.illegal-ad-detector`이고, 사례는
`%APPDATA%\kr.go.nia.illegal-ad-detector\cases\<케이스 번호>\`에 저장된다
(USER_MANUAL.md, 2026-10-20). WebView2 Runtime이 없는 PC에서는 설치 관리자가
bootstrapper를 내려받으므로 네트워크가 필요하다. 이 방식의 오프라인 설치는
검증하지 않았다. 현재 설치 파일은 코드 서명이 없다.

### 8.2 오프라인·무GPU 정책

- 공식 네 기법 판정은 로컬 DOM·CSS·기하·유니코드 분석으로 이루어진다. 모델이
  없어도 동작한다.
- OCR과 임베딩은 선택적 근거 단계다. 모델·참조·언어 데이터는 빌드 시 고정
  SHA-256과 크기로 검증해 패키지에 포함하고, 점검 중에는 내려받지 않는다.
  이미지·문자를 외부 AI 서비스로 전송하지 않는다(DATA_HANDLING_KO.md).
- 모든 추론은 CPU로 수행한다. 비전 인코더는 `min(6, availableParallelism())`
  intra-op/1 inter-op, 문자 인코더는 2/1, 신경망 OCR은 1/1이다. GPU·CUDA·NPU를
  요구하지 않는다.
- 모델 자산은 문자 FP32 + 이미지 8비트 가중치 구성으로 6개 파일
  `1,312,154,937`바이트다. 전체 INT8로 낮추면 경계 문구에서 판정 부호가
  바뀌어 기각했고, 문자 인코더는 FP32로 유지했다
  (EMBEDDING_QUANTIZATION_20261022.md).

### 8.3 성능 측정

Windows 11 VM(4 논리 CPU, 8GiB, GPU 없음)에서 생성한 200페이지 시나리오를
패키지된 워커로 실행한 기록이 있다. 199페이지 확인, 1페이지 의도적 실패,
TP 21/FP 0/FN 0, 모든 동시성에서 공식·상세·추가 결과 검증 통과.

### 8.4 현재 검증 상태

Windows에서 실제로 관측된 것은 2026-10-09 빌드(후보 565)다. 다음이 확인됐다.

- 실제 사람 사용성 평가와 보조기기 판독.

## 9. 기대 행정 효과

정량 효과를 주장할 근거는 아직 없다. 현재 근거로 말할 수 있는 범위는 다음과 같다.

- **점검의 반복 가능성**: 주소 하나로 하위 페이지·프레임·댓글까지 같은 기준으로
  점검하고, 같은 조건이면 같은 결과를 낸다. 담당자 교체나 시점 차이에 따른
  판단 편차를 줄이는 것이 목적이다.
- **근거 기반 시정 요청**: 원문, 페이지 주소, 선택자, 화면 캡처, 판단 근거가
  한 건에 묶여 남으므로, 게시자·유지보수 업체에 "무엇을 고쳐야 하는지"를
  기술 용어 없이 전달할 수 있다.
- **미확인 범위의 명시**: 접근 실패·시간 초과·수집 상한을 숨기지 않는다.
  "점검했으나 0건"과 "점검하지 못함"을 구분하는 것 자체가 행정적 책임 소재를
  명확히 한다.
- **외주 점검 보완**: 상시 도구로 1차 스크리닝을 하고, 애매한 건만 사람이
  검토하는 운영이 가능하다. 다만 이 운영 방식의 비용 절감 효과는 측정하지
  않았다.

## 10. 독창성

1. **은폐와 광고를 분리한 2축 판정.** 은폐 신호만으로 판정하지 않으므로 정상
   웹 구현(접힌 메뉴, sr-only 텍스트, 애니메이션 상태)을 위반으로 만들지 않는다.
   반대로 광고 문구만으로도 판정하지 않으므로 본문에 인용된 사례가 오탐이 되지
   않는다.
2. **위치의 재현성.** 선택자 유일성·왕복 검증과 iframe `>>>` 직렬화로, 탐지
   항목이 나중에 같은 요소를 다시 가리킬 수 있는지 확인한 뒤에만 저장한다.
3. **비용 사다리와 게이트.** 32후보 수집 → Tesseract → 저신뢰 PNG만 PP-OCRv5 →
   규칙 미해결분만 문자 임베딩 → 극단 저해상도만 이미지 임베딩. 각 단계는 앞
   단계의 결과에만 반응하며, 공식 판정은 첫 두 축에서 이미 끝나 있다.
4. **공식 출력과 확장 지능의 분리.** 네 기법 결과는 `result.json`, 확장 단서는
   `result_extra.json`, 사람의 판단은 `review.json`으로 나눈다. 어떤 확장도
   공식 건수를 부풀리지 않는다.
5. **전문가/비전문가 화면 분리.** 같은 엔진 위에 간단 모드와 고급 모드를 두고,
   모드 선택이 탐지 결과나 네트워크 조건을 바꾸지 않게 했다(ADR-0016).
6. **오프라인 공식 경로.** 모델을 쓰되 모델 없이도 공식 판정이 성립하고, 모델은
   빌드에 고정되어 점검 중 외부 통신을 만들지 않는다.

## 11. 확장 탐지 (`result_extra.json`)

공식 결과와 별도 파일로 다음 네 종류를 기록한다(`packages/contracts/src/result.ts`
의 `EXTRA_FINDING_TYPES`, `packages/evidence/src/extra.ts`). 모두 `technique`는
`ETC`이고 `extra_finding`으로 종류를 구분하며, 공식 파일 검증기와 별도로
검증한다.

| 종류 | 성립 조건 |
| --- | --- |
| `IMAGE_ONLY_ILLEGAL_AD` | OCR 의미, 독립 보강 근거, 같은 화면의 동등한 DOM 광고 문구 부재가 모두 성립. 외부 목적지는 관측만 하고 방문하지 않음 |
| `REUSED_AD_CREATIVE` | 지각 해시 계열이 2회 이상 관측 |
| `AD_INFRASTRUCTURE_CORRELATION` | 동일 광고 증거가 2개 이상 페이지에서 관측 |
| `ZERO_WIDTH_OBFUSCATION` | 광고 의미 문맥 안에 U+200B~U+200D, U+FEFF 포함 |

이미지 전용 판정은 여러 차례 보수적으로 조여졌다. 예를 들어 특정 입금 유도
표현(퍼센트 값, 콤프·롤링·페이백·첫충 중 서로 다른 2개 이상이면서 콤프·롤링 중
최소 1개 포함, 입금·첫충 신호, 관측된 외부 목적지)을 요구하고, 공공 신고·교육
문맥과 일반 쿠폰·무료체험·게임 재화는 제외한다. 이미지 임베딩 경로는 실제
OCR 중 하나에 숫자 단서가 있어야 하며, 브랜드 이름만 읽힌 경우에는 승격하지
않는다(DETECTION.md; OCR_GROUNDING_20261021.md).

## 12. 현재 한계와 남은 검증

이 절은 제출 문서에서 가장 중요한 부분이다. 다음은 해결됐다고 주장하지 않는다.

**탐지 품질**

- 실제 사이트 이미지 광고 재현율은 여전히 약점이다. 2026-10-14 블랙툰 실사이트
  점검에서 공식 탐지는 1건이었고, 그 1건은 보이는 배너가 아니라 `display:none`
  조상 아래의 숨은 내비게이션 문구 "보증토토"였다(OFFSCREEN). 당시 이미지
  분석은 후보 8개 확보·OCR 6건 수행·상한으로 2건 제외였고, `첫충70%`를 읽은
  1건은 독립 보강 근거가 없어 2/3으로 보류됐다(DOGFOOD_LEDGER_20261014.md).
  이후 수집 상한은 32후보·40 OCR로 확대됐으나, 그 변경 후의 실사이트 재현율은
  측정하지 않았다.
- 실측 회귀 자료에서 실제 출처 불법 배너 60/60, 실제 정상 광고 오탐 0/74,
  파생 양성 17/18, 파생 정상 오탐 0/38이 기록됐다(EMBEDDING_QUANTIZATION_20261022.md,
  VISION_CPU_OPTIMIZATION_20261022.md). 이는 개발·회귀 자료이며 모집단 정확도도,
  법적 위반 확정률도 아니다.
- 남은 누락이 문서화되어 있다. 극단 축소 파생 BUTTER 1건, 저해상도 소형 배너
  일부, WINNER·MACHUJA 계열의 로고·저해상도 표현. EasyOCR과 Korean TrOCR을
  실제로 비교했으나 신뢰할 수 있는 복구를 얻지 못했고, TrOCR은 알려진 정상
  입력에서 3/10 오탐을 내 기각했다(OCR_ENGINE_COMPARISON_20261021.md).
- GIF는 최대 120프레임만 보고 최대 4프레임을 남긴다. APNG·애니메이션 WebP·
  동영상은 대상이 아니다.

**운영·배포**

- 최신 소스의 Windows 패키지 빌드·설치·화면 수용은 미실행이다.
- D08(재시작 후 두 대상 통합 보고서)은 NOT_RUN이다. 일괄 그룹 복원은 미구현이며,
  개별 사례와 검토 기록만 재시작 후에도 남는다.
- 실사용자 사용성 평가, 보조기기 판독, 조직 외부 수용은 미실행이다.
- 서명되지 않은 내부 평가 후보이며, 코드 서명·배포 채널은 정해지지 않았다.
- 모델 자산 약 1.3GB가 설치 크기에 포함된다. Windows에서의 실제 설치 크기·
  잠금·네이티브 추론 비용은 측정하지 않았다.
- 여러 케이스 인프라 통합, 능동 외부 탐색, 추가 단서에 대한 지속 검토 기록은
  제공하지 않는다.

**성능**

- 위 표의 Windows 수치는 2026-10-07 통합 후보 워커 기준이며, 최신 이미지 분석
  경로(문자 임베딩·이미지 임베딩)를 포함하지 않는다. 이미지 분석 비용을 포함한
  전체 점검 시간은 Linux 개발기(8코어/16스레드)에서 저해상도 배너 6개 기준
  10.024→10.342초, CPU 41.99→35.00초로 측정됐다(VISION_CPU_OPTIMIZATION_20261022.md).
  이는 Windows 성능이 아니다.
