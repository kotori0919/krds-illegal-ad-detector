# App-scoped WARP transport design

작성일: 2026-10-14, Asia/Seoul.
상태: 사용자가 상세 설계 승인 및 구현 계획 작성을 명시적으로 요청함. 구현 전.
기준 소스: `dev/bootstrap`, `c689cf4` 및 현재 작업 트리.

## 목적과 근거

공식 WARP 클라이언트의 설치·실행과 PC 전체 DNS·라우팅 변경 없이,
Windows 탐지 앱의 공개 웹사이트 검사 통신을 WARP 터널로 보낸다.
기존 공개 IP 검증과 검증한 IP로 연결하는 경계는 유지한다.

관측 근거는 `docs/DOGFOOD_LEDGER_20261014.md`에 있다. 공식 WARP가 꺼진
Windows에서 직접 접속·DoH·IP 고정·TLS 버전 변경은 블랙툰 접속에 실패했다.
`usque v4.2.1`의 `http-proxy`와 `l4-http-proxy`는 각각 `warp=on`, 같은 URL의
HTTP 200과 실제 광고 배너 로드를 확인했다. 프록시를 종료한 대조 시험은
`ERR_PROXY_CONNECTION_FAILED`로 끝났다. 이는 독립 Playwright 전송 시험이며,
제품 탐지 엔진이나 기존 IP 고정 프록시의 연동 성공을 뜻하지 않는다.

사용자는 검사마다 터널을 실행하고 기존 IP 검증을 유지하는 방향을 승인했다.
앞선 약관 동의는 시험 장치 1개 등록에 적용됐으며, 배포용 공통 계정이나
다른 사용자의 자동 등록을 승인한 것이 아니다.

## 선택한 구조

```text
Tauri session / Windows Job
  -> Node scanner worker
       -> usque HTTP proxy, authenticated loopback listener
       -> existing public network boundary
            -> validated numeric IP through the usque proxy
                 -> Cloudflare MASQUE -> destination
       -> Playwright through the existing guarded browser proxy
```

앱 전체가 공유하는 터널 대신 검사별 자식 프로세스를 사용한다. 기존 Windows
Job의 세션 소유권과 취소·종료 경계에 포함하기 위해서다. 일괄 검사는 현재처럼
사이트별 독립 세션을 유지한다. 등록 정보는 사용자별로 재사용하지만 실행 중인
터널과 임시 프록시 인증 정보는 세션 간 공유하지 않는다.

첫 구현은 `http-proxy` 모드를 고정한다. 현재 HTTP·HTTPS·Sitemap 요청을
동일한 전송 경계에서 처리하기 위한 선택이다. L4 모드의 성능 우위는 관측되지
않았으므로 자동 모드 선택이나 여러 구현의 동시 유지 대상으로 삼지 않는다.

## 공개망 경계와 전체 요청 경로

`PublicNetworkPolicy.resolveTarget`이 URL과 모든 DNS 응답을 검증하고 선택한
정확한 숫자 IP·포트를 전송 계층에 전달한다. 사이트 호스트 이름을 터널 프록시에
다시 해석하도록 넘기지 않는다. 요청마다 현재 정책과 동일한 검증을 수행한다.

다음 세 경로를 모두 같은 전송 계층으로 전환한다.

1. 브라우저 HTTP 요청 전달.
2. 브라우저 HTTPS의 CONNECT 연결.
3. `PublicNetworkPolicy.fetch`를 사용하는 Sitemap 등 Node HTTP 요청.

터널 프록시에 보내는 CONNECT authority는 검증한 IP·포트다. IPv6는 bracket
형식을 사용한다. 원래 HTTP Host와 HTTPS SNI·인증서 호스트 검증은 유지한다.
TLS를 해제하거나 인증서를 대신 발급하는 중간자 프록시를 만들지 않는다.
CONNECT 응답의 상태·헤더·크기를 제한하고, 성공 응답을 확인하기 전에 브라우저에
연결 성공을 통보하지 않는다. Proxy-Authorization은 목적지에 전달하지 않는다.

현재의 socket 수, DNS 답변 수, 헤더 크기, idle timeout, 전역 deadline,
redirect 검증, 요청 취소 및 직접 DNS·QUIC·비프록시 WebRTC 차단을 유지한다.
공개 사이트 검사에서 터널 실패 시 직접 연결로 전환하지 않는다.

기존 수동 입력 평가 호스트와 소유한 로컬 fixture의 정확한 원점 예외는 유지한다.
이 허가는 공개 대상의 비공개 DNS 응답을 허용하는 예외로 확대하지 않는다.
해당 로컬 평가 경로는 기존 직접 연결을 사용하며 WARP 경유로 표시하지 않는다.
시험용 정책 주입이나 임의 프록시·실행 파일 경로를 UI 입력으로 노출하지 않는다.

## 등록과 인증 정보

사용자별 고정 앱 데이터 경로에 WARP 등록 정보를 저장한다. 등록 프로그램이
파일을 만들기 전에 부모 폴더의 Windows ACL 상속을 끄고 현재 사용자와 SYSTEM으로
제한하며, 파일 생성 후에도 권한을 검증한다. 이 단계의 저장 형식은 usque의
JSON이며 평문 파일이다. 동일 Windows 사용자 권한의 다른 프로세스로부터 비밀을
격리하거나 별도 디스크 암호화를 제공한다고 주장하지 않는다. 시험 폴더나 개발자
계정 설정을 사용자 제품 경로의 기본값으로 사용하지 않는다.

첫 사용 시 앱은 Cloudflare 약관 링크와 장치 등록 동작을 표시한다. 사용자가
명시적으로 동의하고 연결 준비를 선택한 뒤에만 등록한다. 검사 버튼, 앱 시작,
등록 오류 또는 자동 재시도만으로 새 계정을 생성하지 않는다. 등록 완료 후에는
같은 정보를 재사용한다. 기존 공식 클라이언트의 키·등록·계정을 읽거나 변경하지
않으며 WARP+ 구독이나 라이선스 변경을 수행하지 않는다.

등록 동작은 한 번에 하나만 실행하고, 소유한 Job과 제한된 실행 시간을 적용한다.
서버 등록 이후 파일 보관이 실패한 경우를 준비 완료로 처리하지 않는다. 실패나
불확실한 결과를 앱의 추가 계정 생성으로 자동 복구하지 않는다.

등록 및 프로세스 출력에서 키·토큰·프록시 비밀번호를 로그, IPC 응답, 화면,
지원 진단, Case, XLSX 또는 빌드 산출물에 넣지 않는다. 프록시는 인증을 켜고
`127.0.0.1`에만 바인딩한다. 설정 파일 경로는 호스트가 관리하며, 웹페이지나
가져온 대상 파일에서 자격 정보·명령·실행 경로를 지정할 수 없다.

호스트가 worker에 전달하는 인자에는 비밀이 아닌 관리 경로만 넣는다. 세션별
프록시 인증 정보는 worker가 생성한다. usque가 요구하는 인증 인자에 전달한
임시 값이나 전체 자식 명령행을 진단에 기록하지 않는다. 동일 Windows 사용자
권한의 프로세스 조회로 임시 인자가 보일 수 있는 범위는 위의 사용자 경계와 같다.

## 실행 수명과 실패

Tauri가 기존 방식으로 Node worker를 Windows Job에 넣는다. 그 worker가 번들
usque를 자식으로 실행한다. 준비·오류 처리는 worker의 AbortSignal과 기존 전역
검사 시간 예산 안에서 끝낸다. 터널 준비에 별도의 무제한 대기나 검사 재시도를
추가하지 않는다. stdout의 공식 JSON 계약을 유지하며 usque 출력은 섞지 않는다.

준비 완료는 프로세스 생성이나 리스너 존재만으로 판단하지 않는다. 인증된 경로로
고정 Cloudflare trace 주소에 제한된 요청을 보내 `warp=on`을 확인한다. 준비
요청은 검사 페이지 수에 포함하지 않고 전역 시간 예산은 소비한다. IP·계정 등
trace의 다른 필드를 수집·보관하지 않는다.

worker의 finally에서 소유한 터널과 연결을 정리한다. 취소·시간 초과·worker
오류·정상 앱 종료에서는 기존 Job 정리까지 적용한다. 앱 강제 종료 시에도 Job에
속한 자식 프로세스가 남지 않아야 한다. 다른 사용자의 usque, 공식 WARP 또는
동명 프로세스를 이름으로 일괄 종료하지 않는다.

등록 미완료, 설정 권한 오류, 실행 파일 누락·해시 불일치, 준비 실패, 실행 중
터널 종료를 구별한다. 준비 실패는 사이트 미검사로 표시하며 안전·광고 없음·
성공 0건으로 표시하지 않는다. 검사 도중 실패 시 이미 보관한 결과는 유지하고
미검사 범위를 표시한다. 외부 CAPTCHA·Challenge 우회나 광고 링크 클릭은 없다.

## 사용자 화면과 저장 계약

연결 준비 화면에는 약관·등록 상태와 실행 가능한 연결 준비 동작을 제공한다.
일반 검사 화면에는 연결 준비 중·연결 실패·검사 진행 상태와 필요한 복구 행동을
표시한다. 운영자가 프록시 포트나 MASQUE·OCR 용어를 입력할 필요는 없다.

공식 `result.json`의 구조와 탐지 의미·판단 계약은 바꾸지 않는다. Case 설정에
전송 종류, 백엔드 및 버전을 추가해 어느 경로로 검사했는지 보존한다. 인증 정보는
넣지 않는다. 기존 review revision, XLSX, Case 전달 및 과거 결과의 바이트는
변경하지 않는다. 연결 준비 성공을 탐지 정확도 향상이나 위반 확정으로 표현하지
않는다.

## 변경 경계

- `packages/scanner/src/public-network.ts`: 검증한 IP에 대한 공통 전송과
  HTTP·HTTPS CONNECT·policy.fetch 연결. 기존 정책 검증은 이 경계에 유지한다.
- `packages/detection/src/worker.ts`, `worker-args.ts`: 등록된 설정으로 터널을
  실행·확인·정리하고 전송을 전달한다. 호스트 경로만 받으며 비밀을 인자로
  직렬화하거나 stdout에 출력하지 않는다.
- `src-tauri/src/main.rs`와 필요한 등록 전용 모듈: 사용자 동의, 관리 경로와
  ACL, 등록 결과 및 비밀 없는 상태, 세션 설정. 기존 Job 소유권을 재사용한다.
- `packages/contracts`, `apps/web/src/host`, 검사 시작 화면: 등록·준비 상태와
  복구 동작만 추가한다. 페이지가 임의 명령이나 네트워크 예외를 만들지 못한다.
- Windows runtime 준비·manifest·artifact verifier: usque 실행 파일과 라이선스를
  검증된 리소스로 포함한다. 검사를 시작하면서 실행 파일을 자동 내려받지 않는다.
- 사용자 문서와 기존 dogfood ledger: 실제 동작, 자격 정보 저장 범위와 증거 갱신.

검증한 usque 버전은 `4.2.1`, commit
`6aa03fc97d12848dce34eedbd187fb1077b5d1ea`다. Windows amd64 archive SHA-256은
`f6f7f0a1a2bc9bcc15cf563ec1f892d00690a92c086b23ed3211b802209099e7`, EXE는
`122f2e40208e81bb814fcb4be4fbbbdc9246860f1f3784f72ae4512b97667e91`이다.
이 파일과 upstream license를 inventory에 포함한다. 새 버전을 묵시적으로
사용하거나 테스트 자격 정보를 패키지에 넣지 않는다.

## 검증과 수용 조건

영구 회귀는 실제 HTTP·TCP·TLS fixture로 소비자가 보는 실패와 경계를 검증한다.
단순 호출 인자 확인이나 현재 UI 문구를 고정하는 테스트는 추가하지 않는다.

- 숫자 IP CONNECT, 원래 Host/SNI 및 정상 인증서 검증이 함께 유지된다.
- 비공개·metadata·혼합 DNS 응답과 비공개 redirect는 upstream 접속 전에 거절된다.
- HTTP, HTTPS, Sitemap이 모두 선택한 전송을 사용하고 인증 헤더가 목적지에 없다.
- 인증 실패, 비정상 CONNECT, 조기 종료, timeout과 취소에서 성공 응답·직접 fallback이
  없으며 열린 연결과 자식이 정리된다.
- 등록 동의 없이 계정이 생성되지 않고 등록 실패 후 자동으로 추가 등록하지 않는다.
- 실제 Windows 번들에서 공식 WARP를 끈 채 승인된 공개 두 대상을 각 1페이지,
  depth 0, 최대 60초로 검사한다. 단순 Playwright probe를 native 결과로 대체하지 않는다.
- 네이티브 검사 취소·정상 종료·오류 후 터널 및 브라우저가 남지 않고 다음 검사가
  가능하다. 원래 설치 후보와 과거 보관 파일·공식 결과·검토 기록의 해시를 비교한다.
- D08의 판단·메모·재열기·통합 XLSX 조건은 별도로 끝까지 검증한다. 터널 접속
  성공만으로 해당 시나리오나 전체 Sprint를 완료 처리하지 않는다.

신규 모델, 탐지 의미 규칙 변경, 자동 다중 재시도, 전역 DNS·라우팅 변경, 공식
클라이언트 제어, 설치 후보 덮어쓰기, push·PR·공개 배포·merge는 이 설계에 없다.
Windows 외 배포 대상에 usque 통합을 확장하지 않는다. 기존 로컬 fixture 및
소스 단위 검증은 플랫폼별 제품 동작과 구별해 유지한다.
