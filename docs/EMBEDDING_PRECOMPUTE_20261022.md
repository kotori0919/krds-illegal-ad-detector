# FP32 고정 문자 벡터 사전 계산 및 처리 비용 비교

2026-10-22. `dev/bootstrap`, HEAD `56fd3563e031ef1850e88b4fdac0c39ead08eea5`의 기존 dirty 작업 위에서 수행했다.

## 구현과 수치 불변 조건

실제 점검에서 매번 하던 고정 문구 20개(양성8·음성12)의 임베딩을 사전 계산해 `text-references.json`으로 배포한다. 같은 인코더 함수, 분류 prefix, 순서, 4문구 단위 batch, 768차원 정규화와 FP32 CPU 모델을 사용했다. 문구·정책·모델 manifest와 벡터 내용의 SHA를 검증하고, 불일치하면 재생성을 요구한다. 빌드 단계와 실제 로드 단계에서 같은 검증 함수를 사용한다.

모델 가중치·정밀도·스레드 수·분류 임계값·공공안내/정상 거래 제외·OCR·GIF 선택·분석 예산은 변경하지 않았다. 이미지 참조 벡터는 이미 사전 계산되어 있었고 그대로 유지했다. 쿼리의 텍스트/이미지 추론은 계속 실제 점검에서 수행한다.

원래 실행 경로의 20개 벡터 15,360성분과 생성본의 최대 절대 차이는 **0**였다. 허용 오차는 측정 전에1e-5로 고정했다. 아래 점검 비교에서도 OCR 원문·대안·선택 프레임·결정·passed는 같고, 코사인/차이 점수는1e-5 안에 있어야 한다.

## 처리 시간

동일 머신/입력/모델/NAS 경로에서 새 프로세스로 매번 점검했다. 각 변형 워밍업1회를 버리고 대표4묶음은 각5회 교차(홀수회 전→후, 짝수회 후→전) 실행했다. 나머지25묶음은 전후 각1회 품질 비교다. 총90측정 receipt+2워밍업이다. 계측 없는 실행본의 전체 `scanSite` 시간이며 브라우저 수집·OCR·보조 분석·정리를 포함한다.

|---|---:|---:|---:|
| 저해상도 실제 양성 6개 | 20.210 [17.521–20.492] | 20.168 [17.251–20.645] | -0.248 [-0.508–0.436] |

음수 차이는 감소다. 중앙값끼리의 차이와 쌍별 차이의 중앙값을 구분한다. 쌍별 부호가 섞이거나 산포가 변화량보다 크면 명확한 속도 개선으로 해석하지 않는다. N5로 P95나 cold-start/설치 지연을 추정하지 않는다.

## 비교 서버의 수집 경로 확인

처음 만든 비교 서버는 Content-Length를 생략했다. 기존 수집기가 크기 미확인 원본 대신 화면 캡처를 사용하면서 정상 묶음14개 중1개가 바이트 한도로 제외됐다. 헤더 없는 진단에서13개 수집/13개 OCR완료/1개 byte-limit, 정확한 크기를 보낸 진단에서14개 모두 완료를 재현했다. 제품 OCR 실패로 오인하거나 이를 정상 음성으로 세지 않았다. 기존 검증 fixture와 같은 헤더를 적용한 뒤 첫 시리즈 전체와 워밍업을 보관하고 최종90+2를 새로 측정했다. 양쪽 진단 원시값·실패 로그·프로토콜 보정·첫 sourceidentity도 보존했다. 구간 profile 역시 올바른 헤더에서 다시 실행했다. 제품의 크기 미확인 자원에 대한 화면 캡처 fallback 및 예산 제한 자체는 변경하지 않았다.

CPU FP32, Gemma2/1·신경OCR1/1 스레드. 이미지 섞기 seed1701. 모델은 승인된 NAS의 기존 동일 파일이다. 자체 테스트/빌드/모델 probe는 정식 계측 전에 종료했고, 다른 데스크톱·백그라운드 Chrome 및 별도 ML 작업 부하와 전력/온도는 통제하지 못했다.

```sh
npm run prepare:embedding-references  # 고정 문구/모델 변경 시 명시적으로 재생성
npm run build:scanner
npx vitest run packages/evidence/test/text-reference-data.test.ts packages/evidence/test/ocr.test.ts packages/evidence/test/image-embedding.test.ts --maxWorkers=1
KRDS_TEST_UNSANDBOXED=1 node benchmarks/embedding-precompute.mjs
python3 artifacts/embedding-precompute-20261022/summarize.py
```

Benchmark는 기존 receipt 덮어쓰기를 거부한다. 재측정은 별도 evidence 디렉터리를 지정하도록 프로토콜·출력 경로를 명시적으로 준비해야 한다. `--freeze before/after`는 해당 시점 canonical build를 동결하므로 과거 before를 현재 코드로 다시 만들면 안 된다. 보관된 before/after-runtime, before-source, inputs, protocol, source-identity와 원시값을 사용한다. sandbox 예외는 직접 소유한 loopback fixture만 사용한다.

빌드된 worker는 `text-embedding-data/text-references.json`을 오프라인으로 읽는다. 일반 빌드에서 문구를 다시 추론하지 않는다. 생성기는 다운로드 없이 기존 모델 캐시6파일의 크기/SHA를 검사한 뒤 canonical 인코더를 사용한다. 모델 파일이 없으면 먼저 해당 고정 모델을 준비해야 한다. Python은 이 분석 집계에만 사용하며 제품 런타임 의존성을 추가하지 않았다.
