# 사용자 매뉴얼 — 현재 빌드 안내

2026-10-09 도입 후보의 3단계 화면 안내입니다. 실제 사이트 점검은 Windows
데스크톱 앱에서 합니다. 브라우저 미리보기에는 예시 데이터가 표시됩니다.

**저장 위치부터 확인하세요.** 점검 완료 후 결과 상단의 **보관 정보**를 열면 실제
저장 폴더와 공식 원본의 전체 경로가 표시됩니다. Windows 기본 위치는
`%APPDATA%\kr.go.nia.illegal-ad-detector\cases\<케이스 번호>\result.json`입니다.
표시된 실제 경로를 우선합니다. `result_extra.json`은 같은 케이스의 추가 분석이며
공식 결과와 구분됩니다. 설치 폴더와 사용자 케이스 폴더는 별개입니다.

## 설치와 제거

검토용 NSIS 설치 파일과 SHA-256은 [RELEASE_CANDIDATE.md](RELEASE_CANDIDATE.md)에
기록되어 있습니다. Windows 11 일반 사용자로 설치·실행합니다. Node나 개발 저장소,
별도의 Playwright·OCR 모델 설치가 필요하지 않습니다. WebView2 Runtime이 없으면
설치 관리자가 bootstrapper를 내려받으므로 네트워크가 필요합니다. 이 방식의
오프라인 설치는 검증하지 않았습니다. 현재 설치 파일은 서명되지 않았습니다.

앱을 정상 종료한 뒤 Windows의 설치된 앱 목록에서 제거합니다. 저장한 결과 파일은
설치 폴더 밖의 사용자가 선택한 위치에 보관하세요. 현재 후보의 정상 제거에서
이 위치의 공식 결과 파일이 같은 해시로 유지되는 것을 확인했습니다.

## 현재 사용 순서

1. **점검 설정**: 사이트 주소를 입력하고 [점검 시작]을 누릅니다.
   [상세 설정]에서 빠른 점검 또는 직접 설정을 선택할 수 있습니다.
2. **사이트 점검**: 현재 확인 중인 페이지, 탐지·실패 수, 경과 시간과 최근 활동을 확인합니다.
   [점검 중지] 후 중지를 확인하면 종료 처리를 거쳐 완료된 페이지의 결과를 확인합니다.
   완료된 결과가 없으면 설정 화면으로 돌아갑니다. 실패한 점검에도 완료된 결과가
   있으면 [완료된 결과 보기]로 열 수 있습니다.
3. **결과 검토**: [공식 탐지]에서 원문·페이지 주소 검색과 기법 필터를 사용합니다.
   [페이지별]에서 확인·실패 상태, HTTP 응답, 최종 주소, 탐지 유형과 검토 완료 건수를
   확인합니다. 탐지가 없는 페이지도 표시되며, 이전 결과에는 페이지별 기록이 없을 수 있습니다.
   [근거 보기]에서 원문, 변환된 문구, 실제 화면 및 위치를 확인하고 검토 완료로
   표시합니다. 캡처가 없으면 그 상태가 표시됩니다. CSS와 선택자는 [기술 정보]에 있습니다.
   [추가 분석]에서 이미지의 인식 원문, 문자 인식 신뢰도, 광고 표현과 규칙 판단 점수·기준을
   확인합니다. 반복되지 않은 이미지도 문자 분석 기록이 있으면 표시됩니다. 인식 실패와
   시간·용량 제한은 별도로 표시됩니다. [점검 범위]는 확인·실패 페이지와 시간 제한 기록입니다.
   중지한 결과에는 완료된 페이지까지만 표시한다는 안내가 나타납니다.
   [결과 저장]에서 건수와 점검 실패 여부를 확인하고 [저장]을 누릅니다.
   파일 선택을 취소하면 결과가 유지됩니다. 저장 완료 후에는 파일 경로가 표시됩니다.
   저장 중에는 완료를 기다립니다. 실패하면 저장 위치를 확인하고 다시 시도합니다.

점검 범위는 자동 점검(200페이지·하위 4단계·25분), 빠른 점검(50페이지·하위
2단계·10분) 또는 직접 설정을 선택합니다. 직접 설정의 제한 시간은 60~1500초입니다.

여러 게시물의 주소가 있으면 **여러 사이트 일괄 점검**에서 대상 파일을 선택하고
미리보기를 확인합니다. **입력한 페이지만**을 선택하면 주소마다 1페이지·깊이 0·
최대 1분으로 점검하며 하위 페이지 링크를 방문하지 않습니다. 선택 페이지에 포함된
이미지·프레임 등의 자료는 기존 공개 네트워크 정책 안에서 확인합니다. 사이트 단위
점검에는 빠른 점검 또는 자동 점검을 선택합니다. 결과와 미점검 범위는 주소별로
분리되며 공식 JSON도 합치지 않습니다.

## 결과 파일과 해석

`result.json`은 네 가지 공식 기법(HOMOGLYPH, JAMO, TRANSPARENT, OFFSCREEN)의
탐지 결과입니다. 추가 분석은 공식 결과에 합산하지 않습니다. 탐지가 0건이어도
사이트 전체에 문제가 없다는 보장은 아닙니다. 실패한 페이지와 제한 시간 도달 여부는
[점검 범위]에서 확인합니다. 외부 광고 목적지는 자동으로 열지 않습니다.

## 보관·다시 열기·담당자 판단

점검 설정 아래의 **저장된 케이스**에서 이전 점검의 주소·시각·원본 탐지 수를
확인하고 **케이스 다시 열기**를 누릅니다. 저장된 원본과 근거를 읽으며 사이트를
다시 방문하거나 새 점검을 시작하지 않습니다. 일부 캡처·추가 분석이 없더라도
유효한 공식 결과는 계속 열 수 있으며 없는 근거는 사용 제한으로 표시됩니다.

**검토 완료**는 읽음 상태입니다. 상세의 **담당자의 판단**은 판단 전·위반 의심·
정상으로 판단·추가 근거 필요 중에서 별도로 선택합니다. **검토 메모**에는 직접
작성한 내용을 보관합니다. 이 세 가지는 원본 탐지 결과를 바꾸지 않습니다.
변경하면 자동 저장하며, 결과 상단의 **검토 기록 저장됨**을 확인한 뒤 종료하세요.
저장 대기 중 앱을 강제 종료한 수정은 보관되지 않을 수 있습니다.

저장 오류나 다른 창과의 수정 충돌이 나면 작성 중인 메모를 화면에 유지합니다.
권한·남은 공간을 확인한 후 **현재 메모를 유지하고 저장 재시도**를 누릅니다.
다른 창의 최신 기록을 읽되 현재 수정한 항목의 메모·판단을 우선 저장합니다.
같은 항목을 여러 창에서 동시에 수정하지 않는 것이 좋습니다. 브라우저
미리보기에서는 영구 보관을 지원하지 않으며 이 상태를 명시합니다.

**엑셀 보고서 저장**은 검색·필터와 관계없이 전체 원본 기록, 점검 범위, 사람의
읽음 상태·판단·메모와 케이스 번호·정책 버전·저장된 수정 번호를 담습니다.
주소와 메모는 텍스트로 보관하고 수식·활성 링크로 실행하지 않습니다. 보고서를
만들기 전에 검토 기록 저장 완료를 확인하세요.

## 전달·백업·삭제·진단

**전달 폴더 저장**은 선택한 케이스를 다른 폴더로 복사합니다. 받는 담당자는
**전달 케이스 가져오기**에서 해당 케이스 폴더를 선택합니다. 가져오기는 공식
원본과 내부 형식을 검사하고 경로 탈출·심볼릭 링크·실행 파일 등 지원하지 않는
내용을 거부합니다. 전달받은 HTML을 앱 안에서 실행하거나 누락된 근거를 인터넷에서
자동 다운로드하지 않습니다. 다른 팀에 전달하기 전에 원문에 개인정보가 있는지
담당자가 확인하세요. 기관 보존 기간을 앱이 임의로 정하지 않습니다.

업그레이드 전에는 필요한 케이스를 전달 폴더로 백업합니다. 복원은 가져오기로
실행하고 케이스를 다시 열어 원본 수와 검토 메모를 확인합니다. 새 형식을 이전
앱이 읽지 못할 수 있으므로 되돌리기 전에 호환성과 백업을 확인하세요. 정상
제거와 케이스 삭제는 다릅니다. **케이스 삭제**는 주소·케이스 번호·원본 수와
삭제되는 근거·판단·메모를 확인한 뒤 실행하며 앱에서 되돌릴 수 없습니다.
별도로 저장한 전달·백업 폴더는 유지됩니다.

**설치 진단 미리보기**는 도구·정책·케이스 형식 버전과 보관 위치 등을 화면에
보여 줍니다. 원문·쿠키·인증정보를 포함하지 않습니다. 경로의 사용자명 등은
전달 전에 확인하고 **확인한 진단 내용 복사**로 필요한 경우에만 전달하세요.
진단이나 발견 내용을 자동으로 외부 기관·서비스에 전송하지 않습니다.

## 검증 범위

현재 설치본의 설치·실제 점검·근거 검토·제거, 제한 시간 후 네이티브 저장,
응답하지 않는 워커의 정리와 새 점검은 [RELEASE_CANDIDATE.md](RELEASE_CANDIDATE.md)의
Gate A/B/C에서 확인합니다. `DRY_RUN.md`의 다른 설치본 기록은 과거 검증입니다.

OCR은 선택한 광고 이미지에 대한 한국어·영어 CPU 문자 인식입니다. 이미지 수집은
최대 8페이지, 문서당 8후보·250,000바이트, 서로 다른 OCR 이미지 6개로 제한됩니다.
페이지 확인 완료가 모든 이미지 분석 완료를 뜻하지 않습니다. 전체 후보 수가
알 수 없거나 제한으로 제외된 경우 화면의 점검 범위를 확인하세요. 선택적 학습
VLM은 비활성화되어 있습니다. 새 케이스의 검토 상태·판단·메모는 공식 원본과
분리해 저장됩니다. 과거 RC의 설치·제거 기록은 새 도입 후보의 Windows 수락을
증명하지 않습니다. 새 후보의 네이티브·설치·실제 Excel 표시·보조공학 검증은
후보별 수락 기록에서 OBSERVED/NOT_RUN 구분을 확인하세요.
