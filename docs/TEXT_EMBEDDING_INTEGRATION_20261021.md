# 문자 임베딩 보조의 실제 점검 경로 통합과 검증

2026-10-21, `dev/bootstrap` / HEAD `56fd3563e031ef1850e88b4fdac0c39ead08eea5`의
미커밋 변경이다. 일반 점검의 OCR 뒤에 문자 전용 EmbeddingGemma 2 보조를 연결했다.
공식 네 가지 은닉 기법과 `result.json`은 그대로이며, 추가 항목은 사람이 확인할
검토 후보다. Windows 검증·패키지 생성·공개 배포는 실행하지 않았다.

## 구현과 실행 경계

`packages/detection/src/scan.ts`의 `scanSite`가 공식 JSON을 먼저 확정하고, 기존
전체 선택 OCR을 완료한 뒤 나머지 외부 연결 배너에 보조 비교를 수행한다.
기존 규칙의 양성은 유지한다. 공공 신고·교육·예방 안내, 실제 외부 목적지가 없는
이미지, 같은 visible DOM 문구와 중복인 이미지는 보조로 추가하지 않는다.

`packages/evidence/src/ocr.ts`의 `analyzeText`는 기존 OCR 자식 프로세스와 직렬
큐를 재사용한다. `ocr-worker.ts`가 필요할 때 한 번 모델을 초기화한다.
`text-embedding.ts`는 ORT CPU FP32/2스레드, 768차원 정규화, 공식 Classification
접두사와 기존 실험의 고정 한·영 설명16개를 사용한다. 최대 양성 코사인에서 최대
음성 코사인을 뺀 margin이0 이상이면 보조 통과다. 확률이나 보정된 신뢰도가 아니다.
모델·설명·기준을 새 정답에 맞춰 학습하거나 광고주 목록으로 허용하지 않았다.

자식 프로세스의 시간 초과/취소는 SIGKILL과 close 정산을 거치며, 부모 연결이
사라지면 자식도 종료한다. 전체 점검 마감과 마지막 출력 여유 시간을 그대로 쓴다.
모델 초기화 실패는 unavailable로 캐시되어 매 이미지마다 초기화하지 않는다.
오류·중단·한도 초과는 OCR 원문/기존 판정을 보존한다. 4096 UTF-16 단위/256토큰을
넘는 입력과 예약 미디어 토큰 구문은 원문을 바꾸지 않고 비교 불가로 처리한다.

`image-only-ad-v4-text-review`는 의미 보조·외부 연결·DOM 중복 없음의 범주 점수3/3을
쓴다. 모델의 margin/0과 구분한다. 실제 OCR과 literal `matchedTerms`를 보존하고,
모델이 추정한 문구를 OCR 매치로 만들어 넣지 않는다. `ImageAnalysis.textEmbedding`
필드에 모델/리비전/유사도/시간 또는 불가 사유를 남긴다. TS·Rust가 이 근거와
목적지·OCR·추가 항목의 연결을 검증한다. 간단/고급 화면과 XLSX는 ‘검토 필요’를
표시하며 고급 정보에서 수치와 모델을 확인할 수 있다.

## 모델 재현성과 비용

- ONNX: `onnx-community/embeddinggemma-2-ONNX`, 고정 리비전
  `daa72c51243991dfcaf9f9137d2c573d8f7790c0`.
- Node26.8.1, `onnxruntime-node@1.30.0`, 순수 JS `@huggingface/tokenizers@0.2.0`.
  제품에 Python/Transformers.js 전체나 이미지·영상·음성 인코더를 추가하지 않았다.
- 이전 Python의25개 벡터와 JS/ONNX 비교: 최대 성분 오차3.20e-7,
  코사인 오차2.98e-12, margin 오차3.37e-7. 사전 허용치1e-4/1e-5 이내,
  margin0 및0.05 판정 변화0. 새 평가 자료를 쓰지 않은 호환성 검사다.
- 텍스트 그래프/가중치/토크나이저 합계 약1.12GB. `manifest.json`에 크기·SHA-256·
  고정 다운로드 URL을 선언했다. 빌드 시 스트리밍 검증/다운로드하고 동일 파일시스템
  staging에는 hardlink한다. 점검 중 모델 다운로드·원격 AI 전송은 없다.
  제품은 `/dev/shm` 실험 캐시에 의존하지 않는다.
- Windows용 모델 리소스 포함 설정은 연결했지만 lock 갱신·네이티브 추론·설치기
  생성/검증은 보류다. 이 Linux 결과를 Windows 성능으로 해석하면 안 된다.

## 자료와 비교 방법

모델 정책과 라벨을 추론 전에 고정했다. 매니페스트에 원본/HTML/주소/해시/크롭 좌표,
치수, 사람이 판단한 이유와 중복 검토를 보관했다. 정답/파일명/광고주 도메인을 모델에
넣지 않고 실제 OCR만 입력했다. 이전8개 배너와 삼성/LG6개 광고는 새 자료에 쓰지 않았다.

1. 주 자료: [2024-10-16 머니투데이 보도](https://www.mt.co.kr/tech/2024/10/16/2024101523264186082?kakao_from=mainnews)의 실제 불법 웹툰 도박 광고 화면에서 기존 소재와
   다른 광고주·도안10개를147×40 원래 해상도로 잘랐다. 열 개 모두 하나의 보도 화면이며
   원 사이트는 미상이다. 독립 사이트10곳이나 현재 실사이트 표본이 아니다.
2. 보조 자료: 같은 날 저장한 기존 블랙툰 화면에서 이전8개와 다른 광고주10개를
   198×60으로 잘랐다. 소재는 새 것이지만 이전 자료와 사이트·날짜·화면 계열이 같다.
3. 정상 기본 자료: KB와 넥슨의 실제 정상 홍보9개, 실제 보이스피싱 예방 안내1개.
   게임 이미지 중 일부는 글자가 적은 그림이다. 두 양성 코호트에서 공유하며 분모를
   두 번 더하지 않는다.
4. 추가 문자 많은 정상 자료: 코오롱몰 쿠폰 광고2개, KB 정상 대출 한도, 넥슨 캐시
   구매 상품 부분1개. KB는 기본 대출 광고와 같은 캠페인의 다른 구성 요소다.
   원본 JPEG/PNG와 넥슨 원본의 실제876×750 크롭을 사용했다. 합성 문구가 아니다.

광고 화면에는 원래 href/DOM/개별 광고 파일 URL이 없으므로 모든 양성·음성에 똑같은
시험용 외부 링크와 banner marker를 붙였다. 목적지의 실제 존재·차단·광고 운영자를
검증한 것이 아니다. canonical 수집→OCR→보조→extra/detail 경로를 소유 loopback에서
실행했다. 공개 사이트의 격리를 해제하지 않았다.

세 번 짝지어 baseline(보조만 끔)과 기본 보조 경로를 실행하고 두 번째는 순서를
뒤집었다. 각 점검은 새 자식/모델로 시작한다. OS 캐시는 완전 cold로 강제하지 않았고
CPU를 독점하지 않았다. 초기화와 OCR을 포함한 전체 wall time이며 host 저장·내보내기
시간은 포함하지 않는다. 학습이나 난수 증강이 없으므로 seed를 바꾼 학습 반복으로
표현하지 않는다. 쌍별 OCR 원문/신뢰도/엔진 차이는0건이다.

## 최초 오탐과 공개한 사후 보완

최초 고정 정책은 새 출처5/10, 보조 블랙툰9/10을 세 번 동일하게 찾았지만 정상 기본
자료에서2/10을 잘못 추가했다. 실제 게임 그림의 OCR `+`와 KB의 보이스피싱 제로
캠페인이다. 각각 margin0.002735736/0.023191517이었다. 결과는
`initial-observed.json`과 `initial-runs/`에 그대로 보존했다.

이를 근거로 의미 있는 문자(Unicode letter)가 없는 OCR을 보조에서 제외하고,
보이스피싱 제로·예방·주의·캠페인/피싱 신고 안내를 기존 공공안내 제외에 더했다.
임계값·설명·모델은 바꾸지 않았다. **이 보완 후 원래 새 자료는 회귀 검증 자료**이며,
오탐0을 독립 holdout의 무편향 성능으로 주장할 수 없다. 추가 문자 광고4개는 보완 전에
별도로 라벨을 고정하고 보완 후 처음 점수를 확인한 음성 검사다. 새 양성의 추가
독립 재검증까지 했다고 주장하지 않는다.

첫 추가 자료 replay에서는 시험 서버의 Content-Length 부재로 원본 대신 PNG 캡처를
사용했고, 쿠폰 광고1개가 개별250KB 상한에 걸렸다. 이 결과를 정상 음성으로 세지
않았다. `revised-screenshot-observed.json`에 보존하고, 올바른 MIME/Content-Length로
원본을 제공해 최종 비교를 다시 했다. 제품의 수집 상한을 늘리거나 예외 처리하지 않았다.

## 최종 측정

수집 제외/실패 없이34개 모두 OCR 완료했다. 아래 값은 세 번 모두 같은 탐지 수이며,
시간은 전체 점검 중앙값이다. 양성 탐지는 사람이 검토할 후보를 뜻한다.

| 자료 | 보조 끔 | 보조 켬 | 전체 시간 전→후 |
| --- | ---: | ---: | ---: |
| 별도 보도 화면의 새 불법 배너10개 | 0/10 | 5/10 | 6.047→7.404초 |
| 이전 미사용 블랙툰 소재10개 | 1/10 | 9/10 | 6.600→7.973초 |

| 추가 문자 많은 정상 광고4개 | 오탐0/4 | 오탐0/4 | 1.445→2.702초 |

주 자료의 시간 범위는 전5.962–6.130초, 후7.387–7.673초이고, 순수 보조 요청 합계는
초기화를 포함해1.344–1.351초다. 보조 블랙툰은 전6.510–6.601초,
후7.919–8.027초다. 정상 광고는 총13개 이미지+공공안내1개, 오탐0/14이며
중복 음성·반복 실행을 새로운 표본으로 더하지 않았다. 실제 정상 자료가 몇 출처와
캠페인에 몰려 있고 초기 오탐을 본 뒤 보완했으므로 현장 오탐률0%를 의미하지 않는다.

주 자료의 남은5개는 888Asia, 우주선, 미라클, WINNER, MACHUJA다.
OCR이 제안·입금·보너스 핵심 표현을 잃고 이름/숫자/깨진 글자 위주로 남았다.
미라클은 `SPORTSS CASNO`처럼 손상됐고 모델 margin도-0.000514였다.
기준을 이 표본에 맞춰 낮추지 않았다. WINNER는 숫자뿐이라 보조를 실행하지 않는다.
블랙툰의 남은1개 BC.GAME도 이름·가입 문구만으로는 음성 설명보다 가깝지 않았다.
수집·예산 부족으로 이6개가 빠진 것은 아니다. `remaining-misses.json`에 원문과 점수를
남겼다. 문자 보조는 OCR이 잃은 픽셀을 보거나 글자를 복원하지 못하므로 원본 해상도/
애니메이션 다중 프레임/OCR 개선 과제가 남는다. 뉴토끼 원본 배너24개는 연결 초기화로
확보하지 못했으며 뉴토끼 탐지율을 측정했다고 주장하지 않는다.

## 재현·검증 파일

- `benchmarks/text-embedding-holdout.mjs`: frozen image hash 확인, 동일 외부 링크 조건,
  전체 canonical 비교, 모든 입력의 수집/OCR 완료와 공식 finding0/detail 계약 검증.
- `artifacts/text-embedding-integration-20261021/`: frozen/revised 정책, 입력 매니페스트,
  초기/보완/최종 raw 실행, `summary.json`, `remaining-misses.json`, 환경/모델 parity.
- 실행: `npm run build:scanner`, 소유 fixture 환경에서
  `KRDS_TEST_UNSANDBOXED=1 node benchmarks/text-embedding-holdout.mjs`.
  이 플래그는 시험 harness에서만 쓰며 제품 worker는 읽지 않는다.

검증 명령·최종 상태는 같은 디렉터리의 `receipt.json` 및 ADOPTION_LEDGER를 따른다.
전체 tests/build/typecheck/lint와 Linux 공유 Rust 근거 검사를 실행하며, Windows는
미실행이다. 보조 통과/실패/취소에서 이미 확정한 비어 있지 않은 공식 JSON의 동일성,
공공안내 제외, 모델 누락 시 OCR 유지, 워밍업 후 deadline/취소/복구, 위조 메타데이터와
간단/고급 화면 표시를 구체적인 회귀 조건으로 검사한다.
