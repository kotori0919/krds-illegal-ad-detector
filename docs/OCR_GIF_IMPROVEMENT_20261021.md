# 작은 배너 OCR과 GIF 선택 누락 개선

2026-10-21, `dev/bootstrap` / HEAD `56fd3563e031ef1850e88b4fdac0c39ead08eea5`의
미커밋 변경이다. 기존 문자 임베딩 보조 뒤에 남은5개 누락을 진단하고, 작은 배너의
독립 OCR 결과를 추가했다. GIF 선택 결함 두 가지도 수정했다. **원래 문제10개 중
3개와 새 정상 광고 오탐2개는 남아 있다.** Windows 검증은 계속 보류했다.

## 원인과 선택한 수정

같은 실제147×40 픽셀에 대해 detector 해상도, 검출 영역, 거부된 저신뢰 줄을 포함한
CTC 출력, 기존 Tesseract 출력을 남겼다. 기존 검출기는 짧은 변736 기준과 긴 변2432
상한으로 이 배너를2432×672까지 확대했다. 일부 큰 글자는 영역으로 잡지 못했고,
원래6픽셀 정도인 글자는 쪼개진 영역으로 인식됐다. 영역을 찾고도 잘못 읽은 경우도 있다.

확대율만4배로 제한하면 888Asia의 `409`가 `40%15%`로, 미라클의 조각난 영문·숫자가
더 온전한 제안 문구로 바뀌었다. 하지만 이 방식으로 전체를 교체하면 기존에 찾던
디자인 등의 판정이 악화됐다. Tesseract 합치기/4배 확대, 경계 반올림 변경, 흑백·반전·
대비 스트레치, 수평 밴드 인식도 개발 자료에서 단독 대체로 충분하지 않아 채택하지 않았다.
실험 기록은 `artifacts/ocr-gif-improvement-20261021/diagnosis/hypothesis.md`와 raw JSON이다.

선택한 수정은 두 결과를 분리해 보존하는 것이다. `scanSite`가 모든 기본 OCR을 먼저
완료한다. 기본 규칙/의미 보조로 이미 찾은 항목은 유지한다. 아직 찾지 못한 외부 연결
PNG 중 높이96 이하·가로세로비3 이상만 같은 PP-OCR 가중치로 최대4배 검출 확대의
OCR을 별도로 수행한다. 원래 결과를 덮어쓰거나 두 문장을 합치지 않고, 실제 기계 출력
각각에 기존 공공안내 제외·규칙·문자 임베딩을 적용한다. 대안이 후보를 추가하면 그
실제 원문이 선택 OCR이 되고, 미선택 기본 원문은 `ocrAlternatives`에 남는다. 추가하지
못하면 기본 OCR과 미선택 대안을 남긴다. 사람이 읽은 정답·오타 교정·광고주 허용목록을
모델 입력에 넣지 않았다. 임베딩 모델·설명16개·margin0은 이번에 바꾸지 않았다.

`LocalOcrBackend`의 같은 직렬 큐·자식·가중치를 재사용한다. 별도 모델/의존성/다운로드는
추가하지 않았다. 각 요청8초와 기존 전체 마감·출력 여유를 유지하며 대안 오류·시간 제한은
기본 결과를 보존한다. 대안 원문4096자 초과는 잘라 저장하지 않고 인식 불가로 처리한다.
선택 원문과 의미 비교 근거는 같은 결과를 가리키고 TS·Rust가 추가 원문 최대1개와
크기/상태/신뢰도를 검사한다. 간단 화면에는 비교/실패 안내, 고급 정보와 XLSX에는
각 원문·엔진·실패 사유를 구분한다. 늦은 OCR 중 취소가 성공으로 남던 상태도 최종
자식 종료 후 신호를 다시 확인하도록 바로잡았다. 공식 JSON은 앞서 확정한 그대로다.

## GIF의 서로 다른 누락 두 가지

읽기 전용 생산 코드 snapshot과 소유 loopback 제어로 다음을 재현했다.

- 800×200 GIF의14px 회색 문구가20ms 나타나도8×8의4bit RGBA signature는 흰 화면과
  같았다. 중복 제거가 문구 frame1을 버리고 흰 frame0만 남겼다.
- 고대비 장식4개 다음20ms 문구가 나오는5프레임 GIF에서 전역 대비 상위4개가 장식만
  골랐다.5개 모두 검토했고 예산도 충분했지만 frame4를 버렸다.

누락된 원래 두 프레임을 OCR에 직접 넣으면 모두 `카지노 가입 보너스 지급`, confidence0.96으로
읽혔다. 따라서 이 두 제어는 OCR이 아니라 선택 단계 실패다. 수정은128×32의 더 세밀한
signature/edge, 검토할 인덱스 구간을4개로 나눈 분산 선택이다. 기존 creative hash는
8×8 그대로이며,120프레임·약3초 decode·최대4프레임 보관·250KB/4MP 상한을 유지한다.
모두 decode해도 서로 다른 내용이 선택에서 빠지면 `animation-partial`로 표시한다.

같은 시간 구간에서 고대비 장식과 문구가 경쟁하는 별도 제어는 여전히 문구를 놓친다.
120번째 이후 프레임도 기존 상한으로 분석하지 못한다. 확대된 signature도 원본 픽셀의
완전 비교가 아니므로 모든 순간/미세 변화의 보존을 보장하지 않는다.

**실제 집행된 불법·정상 애니메이션 GIF 원본은 확보0개다.** 외부 배너 제작 포트폴리오
원본은 진단용으로 분리했고 실제 광고 분모에 넣지 않았다. 아래 GIF 성적은 파생 제어다.
정상 광고 원본6개에 흰 화면→20ms 광고→흰 화면을 붙인 추가 GIF도 파생 회귀로 분리했다.
정지 실제 광고의 색을 GIF palette로 양자화한 것으로 독립 광고6개나 실제 집행 GIF가 아니다.

## 동결 자료와 비교

수정 전 `scanSite`/OCR worker를 artifact에 복사한 실행 snapshot과 수정 후 canonical
`scanSite`를 같은 세션에서3회 쌍 비교했다. 두 번째는 실행 순서를 뒤집었다. 각 점검은
새 자식/모델 초기화를 포함한다. CPU를 독점하거나 OS cache를 강제 cold로 만들지 않았다.
Node26.8.1/ORT1.30.0/tokenizers0.2.0/CPU FP32, Ryzen7 9700X, RAM32GB 환경이다.
학습/난수 증강 없이 반복했고 임베딩 수치 비교 허용치는 기존1e-5를 유지했다.
촬영 화면의 원래 href가 없어 모든 양성·음성에 같은 시험용 외부 링크와 banner marker를
붙였다. 실제 사이트 접근·목적지·차단·법적 위반을 검증한 수치가 아니다.

기존 자료는 문제 MT10개, 블랙툰 기존8개+이전 미사용10개, 실제 정상 홍보13개+공공안내1개다.
새 자료는 점수를 보기 전에 frozen manifest로 고정한 의심 광고9개+실제 정상 광고10개다.

- 양성4개는 다른 CivicNews2016/2022 보도 화면에서 나온 실제 광고,5개는 기존 MT 화면의
  미사용 광고주·도안이다. 새9개는3개 화면에 묶여 있고5개는 이미 사용한 출처 화면과
  상관이 있다. Civic4개는 전후 모두4/4였으며 MT 미사용5개는2/5→5/5였다.
- 정상10개는 해커스6개(500%/300%/100% 환급·무료·쿠폰·장학금), IBK 정상 대출1개,
  GS SHOP 할인/상품/쿠폰3개다. 원본 JPEG/PNG 바이트·해상도를 유지했다.
- 원본/HTML/URL/해시/크롭 좌표/라벨/중복 검토는 `fresh/manifest.json`과 README에 있다.
  TK/위너스는 이전 WINNER 명칭과 겹칠 우려로 점수 전에 제외했다. 모자이크 사진과
  제작 샘플을 실제 양성으로 대신 세지 않았다. MT 확대 뷰어도 동일600×337 원본만 제공했다.

MT10개의 시간 범위는 전10.382–10.861초, 후10.996–11.288초다. 쌍별 증가 중앙값은
0.427초(0.425–0.875초)로, 개별 중앙값의 차이와 구분한다. 새9개는 쌍별-0.666~+0.408초로
변동 부호가 갈리므로 속도 개선을 주장하지 않는다. GIF도 쌍별-0.399~+0.379초이며
실험 순서/호스트 변동이 있어 속도 개선 근거가 아니다. 같은 자료3회는 새로운 표본3배가
아니다. 이전 회차의7.40초와 이번11.257초를 다른 세션 간 성능 회귀로 단정하지 않는다.
이번 수정 전 snapshot도 같은 호스트에서10.570초였으며 통제 비교는 이번 쌍이다.

기존 누락에서 회복한 것은 888Asia·미라클, 블랙툰 호빵맨·BC.GAME이다. 남은 MT3개는
우주선(`첫출전40%` 등), WINNER(거의 숫자뿐), MACHUJA(이름 위주)다. 현재 모델이
실제 제안 문구를 충분히 읽지 못했으며, 이를 잡으려고 semantic 임계값을 낮추지 않았다.
원본 해상도/원본 GIF와 다른 인식기의 검증이 필요하다. 모든 누락을 해결했다고 주장하지 않는다.

새 정상 FP2개는 해커스 토익 무료교재와 전기기사300% 환급 광고다. OCR 원문을 의미
보조가 광고 쪽으로 오분류했고 margin은0.016555/0.002843이다. 수정 전후 정확히 같은
두 파일이 세 번 모두 통과했으며 새 대안 OCR을 시도한 사례도 아니다. 이번 개선으로
증가하지 않았지만 **미해결 오탐**이다. 새 정답을 보고 설명/임계값/광고주 예외를 맞추지
않았다. 정상24개 이미지 합계FP2이지만 몇 출처에 묶인 선택 표본이라 현장 FPR 추정이 아니다.

추가 파생 정상 GIF6개는 세 번 모두 FP1/6→1/6이었다. 같은 토익 무료교재 광고가
계속 오탐이었다. 전체 시간 중앙값3.519→3.651초, 범위 전3.322–4.462초/후3.259–3.860초다.
별도 `normal-gif-observed.json`에 전후3쌍 결과를 보관한다.
정지 광고와 분모를 중복 합산하지 않는다. 정상으로 보이는 화면을 단순히 수집 실패로
넘겨 FP0으로 계산하지 않고, 모든 입력의 acquisition/OCR 완료를 benchmark에서 확인한다.

## 검증·재현과 한계

`benchmarks/ocr-gif-recall.mjs`가 frozen hash, 같은 외부 링크 조건, 실제 canonical 경로,
공식 finding0, TS detail 연결과 모든 입력의 수집/OCR 완료를 검사한다.
실행은 소유 로컬 fixture에서 `KRDS_TEST_UNSANDBOXED=1 node benchmarks/ocr-gif-recall.mjs`다.
추가 정상 motion 진단은 `--normal-gif-diagnostic`이다. 이 flag는 공개 사이트나 제품
worker의 격리 설정을 낮추는 권한이 아니다.

통합 검증은 `npm run build:scanner`, `npm run build`, typecheck/lint,
owned fixture 전체 tests645passed1skipped, Linux 공유 Rust evidence7passed다.
대안의 실제40%15% 회복·기본 원문 보존, GIF 누락 두 제어의 실제 OCR, 기존프레임/상한,
공공안내 제외·모델오류/취소/복구,4096자 초과 대안 거부, 분석 중 취소의 최종 상태,
선택/미선택 원문 UI·XLSX 구분을 검사했다. Windows 빌드·설치·네이티브 실행은 NOT_RUN이다.

읽기 전용 리뷰의 대안 길이/늦은 취소 수정은 최초 paired 모듈 로드 뒤에 적용됐다.
수집한 정상 경로 수치의 알고리즘을 바꾸지 않는 경계 수정이며 새 빌드/전체 검사와
최종 소스의 파생 정상 GIF 비교로 검증했다. source/model hash와 로그는
`artifacts/ocr-gif-improvement-20261021/receipt.json`에 남긴다. raw 입력·초기 실험·
채택하지 않은 전처리·모든 전후 실행을 보존한다. 공식 네 기법·직접 연결/WARP 선택,
단일 사례 인프라 범위는 유지했고 commit/push/PR/배포/제출은 하지 않았다.
