# 접근 제한 페이지의 점검

Cloudflare를 사용하는 사이트라도 정상 페이지가 열리면 점검할 수 있습니다.
`cf-mitigated: challenge` 응답과 실제 보안 확인 화면, HTTP 403/429,
로그인 필요, 연결/시간 초과를 구분합니다. 보안 확인 페이지는 HTTP 200이어도
점검 성공이나 '탐지 없음'으로 계산하지 않습니다. 탐지 결과와 별도로 페이지별
제한 사유, 성공적으로 확인한 범위와 미점검 범위를 결과·엑셀에 보관합니다.

HTTP 429 응답의 `Retry-After`가 유효하면 그 대기 시간을 줄이지 않고 후속 페이지 요청의
시작을 늦춥니다. 남은 전체 점검 예산으로 대기를 감당할 수 없으면 새 요청을
시작하지 않습니다. 현재 URL에 대한 자동 재시도는 없으며 전체 점검 제한 시간·중지가 우선합니다.
전체 사이트 도달 여부와 발견되지 않은 페이지 수는 알 수 없습니다.

대상 사이트 운영 권한이 있는 담당자는 보안 담당자에게 승인된 점검 접근을
요청합니다. 시작 주소와 점검 시간대, 실제 점검 출발지, 필요한 경로와 요청
한도를 제시하고 담당자가 좁은 범위의 허용 규칙을 승인·적용한 뒤 다시 점검합니다.
도구가 Cloudflare 설정이나 계정 권한을 변경하지 않습니다. 운영 권한이 없으면
제한을 보고하고 사이트 담당자에게 승인된 접근 또는 적법한 원문 제공을 요청합니다.
CAPTCHA 해결, IP 회전, 지문 위장, 세션 탈취나 자동 우회 기능은 제공하지 않습니다.

근거: [Cloudflare의 Challenge 응답 식별 문서](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/).
